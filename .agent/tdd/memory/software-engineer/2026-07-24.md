## 2026-07-24 — 007.15 Story B: migration 17 FK-parent rebuild bug

- `initiatives` is an FK _parent_ (`objectives.initiativeId REFERENCES initiatives(id)`); the standard events-style CREATE/INSERT-SELECT/DROP/RENAME rebuild trips SQLite's FK violation counter on `DROP TABLE` of a non-empty parent, even with `PRAGMA defer_foreign_keys=ON` inside the transaction (verified with a minimal node:sqlite repro — counter never clears since child rows aren't re-touched).
- Fix: `PRAGMA foreign_keys` must be toggled OFF _before_ `BEGIN` and back ON after `COMMIT`/`ROLLBACK` (SQLite's documented 12-step table-rebuild recipe) — a no-op if issued mid-transaction.
- Added an opt-in `disableForeignKeys?: boolean` flag on `Migration` (migrate.ts), defaulting to false so migrations 1-16 are untouched; set it only on migration 17.
- Gotcha worth remembering: any _future_ migration that rebuilds a table referenced by another table's FK (an FK parent) needs this same flag — child-only rebuilds (like the events table) never needed it.
