## S10 final GREEN — B2 decided: flag validation precedes idempotency

- Ulrich amended the epic's Story D with a binding "Flag validation precedes idempotency" rule: a flag that cannot apply to the target (e.g. `--confirm-no-default` on an already-logged_out non-default provider) must be REJECTED, never silently swallowed by the idempotent no-op. Consequence: `logout` is idempotent only when called with no flags.
- Moved the `!isDefault` `UnnecessaryReplacementError` check in `logout-ai-provider.ts` to run right after the both-flags check and BEFORE the corrupt-pointer check and the already-logged_out early return. Final rule order: unknown id -> both flags -> flag-cannot-apply -> corrupt pointer -> already-logged_out no-op (only reachable with no flags) -> is-default branch.
- Reshaped the trailing default-branch chain into `if (isDefault) { replacement | confirmNoDefault | else throw }` so a non-default target with no flags falls straight through to `logout(id)` (previously an `else if` chain that would have wrongly hit `DefaultNeedsReplacementError` for that case after the reorder).
- `remove-ai-provider.ts` left untouched per instruction — it never inspects the target's own `state`, so its flag-on-non-default branch already fires unconditionally regardless of idempotency; no equivalent bug there.
- Verify: typecheck clean, 1578/1578 tests pass, verify:handoff PASS, lint clean, epic Proof reaches `008.1 PROOF OK` (14/14). Live-verified both the false-audit-line fix and no-flag idempotency survival.
