## 008.1 S10 follow-up 2 — replaced flawed rollback test with a spy + compile guard

- Coordinator caught it: the rollback test could be satisfied by reordering production writes
  (logout before setDefault) with no transaction involved — its fake never restored state, so
  "rollback" was unfalsifiable by any real mechanism. Deleted it entirely, did not keep it.
- Replaced with a spy: `RecordingRegistry` logs each mutating call name; `makeSpyUow` logs
  "enter"/"exit" around `fn()` into the _same_ array — asserts full log equals
  `["enter", <writes...>, "exit"]` for both the --replacement and --confirm-no-default paths.
  This can't be satisfied by write-reordering since it pins exact sequence + transaction-call
  count.
- Key finding: those spy tests pass TODAY (GREEN) because production already wraps everything
  in `this.#uow.transaction()` — that wrapping predates the optional-uow blocker. A runtime
  spy literally cannot observe "the uow param is optional" since behavior is already correct.
  Added a third test — a `@ts-expect-error` compile guard on `new LogoutAiProvider(registry)`
  (1-arg) — to give a genuinely-currently-RED signal on the actual deviation. This mirrors the
  established compile-guard convention already used in `add-resource.test.ts` /
  `resource.test.ts`.
- RED confirmed via `npm run typecheck`: `TS2578: Unused '@ts-expect-error' directive` — fails
  now, will pass once uow becomes required (no pass-through default).
- Lesson: when a spy/behavioral test can't distinguish "optional-with-safe-default" from
  "required," that's a signal to reach for a type-level compile guard instead of forcing a
  runtime mechanism (rollback) that doesn't actually exist in the design.
