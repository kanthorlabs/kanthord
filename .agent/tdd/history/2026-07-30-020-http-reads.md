**Seam (GREEN).** `defineRoute` returns `def` unchanged (erased via `as unknown as Route`), so `row.decode`/`row.run`/`row.present` are the exact references passed in (identity test) and a matching decode/run pair passes the decoded value through unchanged (invocation test). **Typechecking note.** `run`'s second parameter is `NoInfer<Input>`, not plain `Input`. With plain `Input`, TS's generic inference treats `run`'s explicit parameter annotation as a priority candidate, so it infers `Input` from `run` instead of `decode` — then the mismatch's type error lands on the `decode` property (verified against an isolated `tsc --strict` repro), not on `run`, where the test's `// @ts-expect-error` comment sits. `NoInfer<Input>` forces `decode` to be the sole inference source for `Input`, moving the mismatch error onto `run` as the test expects, while leaving the matching-pair case and the plain identity/invocation cases unaffected.
