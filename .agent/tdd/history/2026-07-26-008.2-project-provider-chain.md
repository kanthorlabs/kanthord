```
SqliteAiProviderRegistry: shiftRanksFrom then insert at 0 keeps order total; compactRanks turns gaps into contiguous
  Error: near "ORDER": syntax error
      at SqliteAiProviderRegistry.shiftRanksFrom (file:///.../ai-provider-registry.ts:209:8)
```

**Root cause.** The SE appended `ORDER BY rank DESC` to the UPDATE, but SQLite's `UPDATE` statement does not support `ORDER BY` — it produces `Error: near "ORDER": syntax error` (SQL logic error, errcode 1).

The SQLite-safe approach is a **two-phase shift**: first make affected ranks uniquely negative (`rank = -(rank + 1)` avoids collision because every row maps to a distinct new value), then flip back to positive (`rank = -rank`):

```sql
-- Phase 1: shift to negative (no collisions — each row maps to a distinct negative)
UPDATE project_ai_providers SET rank = -(rank + 1) WHERE projectId = ? AND rank >= ?;
-- Phase 2: flip back to positive (now at rank+1 per row, no collision because Phase 1 vacated the range)
UPDATE project_ai_providers SET rank = -rank WHERE projectId = ? AND rank < 0;
```

This avoids the UNIQUE `(projectId, rank)` constraint because the intermediate negative set has no overlap with the original or final ranks.

**Open to Software Engineer.**

- Seam: `SqliteAiProviderRegistry.shiftRanksFrom` at `src/storage/sqlite/ai-provider-registry.ts:205-213`. Replace the single `UPDATE … ORDER BY rank DESC` with the two-phase negative-then-positive UPDATE above to avoid the UNIQUE constraint without using ORDER BY (invalid in SQLite UPDATE).

ATTEMPT-FAILED: 01-assignment-store — ORDER BY in UPDATE is invalid SQLite syntax; use two-phase negative-then-positive shift instead
