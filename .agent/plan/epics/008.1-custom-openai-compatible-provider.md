# EPIC 008.1 — Custom OpenAI-compatible provider + model test CLI

Prereq (by capability, not number): EPIC `008.1-global-ai-provider-registry`
(the `ai_providers` registry + `register ai-provider`) and EPIC
`008.3-daemon-auto-resolve-provider` (the resolved-provider → `sessions.for`
session path). This epic shares the `008.1` number with the global-registry epic
by decision; its real dependencies are the two epics named above.

## Goal

An operator can register a **custom OpenAI-compatible** AI provider — one not in
pi's pinned catalog — into the global registry (008.1) by giving a
`--custom-provider-id`, a `--base-url`, an allowlisted `--api` flavor
(`openai-completions` / `openai-responses`), a `--model`, and an API key. At
session build the daemon reconstructs it via pi's `createProvider(...)` +
`MutableModels.setProvider(...)` under a **session-local runtime id derived from
the record id** (so two custom accounts of the same kind never collide). A new
`test ai-provider --id <id>` CLI builds a real session and asks the model a prompt
(default: "What is today's datetime?"), printing the model's response — the
concrete proof a registered provider actually works end to end. Custom providers
use **static** model metadata (a documented conservative template, operator-
overridable), never dynamic discovery, and a plain-HTTP or private-network
`--base-url` is refused unless `--allow-insecure` is passed. Modeled on
`pi/packages/ai/src/providers/qwen-token-plan.ts`.

## Verification Gate

Gates: `npm run verify` (typecheck + test + verify:handoff + lint + db status)

Proof: hermetic. Starts a local OpenAI-completions-compatible mock that answers
with a fixed marker; registers a custom provider pointed at it; proves
`test ai-provider` reaches the model and prints the answer; and proves the
insecure-endpoint guard.

```sh
set -euo pipefail
D=".data/e2e-0801-custom"; rm -rf "$D"; mkdir -p "$D"
export KANTHORD_DB="$PWD/$D/k.db"
node src/main.ts db migrate >/dev/null

# Local OpenAI-completions mock: streams an SSE completion whose text contains DATETIME-OK.
# (Story D creates scripts/e2e/mock-openai-completions.mjs; it prints its base URL to stdout.)
node scripts/e2e/mock-openai-completions.mjs > "$D/mock.url" 2>"$D/mock.log" &
MOCK_PID=$!
trap 'kill $MOCK_PID 2>/dev/null || true' EXIT
for i in $(seq 1 50); do [ -s "$D/mock.url" ] && break; sleep 0.1; done
URL=$(cat "$D/mock.url")   # e.g. http://127.0.0.1:<port>/v1
printf 'sk-CUSTOM-KEY-SECRET' > "$D/key.txt"

# ── Story E — plain-http/private base URL is refused without --allow-insecure ──
if node src/main.ts register ai-provider --name qwen-bad --custom-provider-id qwen-token-plan \
  --api openai-completions --base-url "$URL" --model qwen-max --value-file "$D/key.txt" \
  > "$D/reg-bad.out" 2>&1; then REG_RC=0; else REG_RC=$?; fi
{ [ "$REG_RC" -ne 0 ] && grep -qiE 'insecure|http|private|allow-insecure' "$D/reg-bad.out"; } \
  && echo "PASS E: http/private base URL refused without --allow-insecure" \
  || { echo "FAIL E: insecure endpoint accepted (rc=$REG_RC)"; cat "$D/reg-bad.out"; exit 1; }

# ── Story A/B — register the custom provider (with the explicit insecure opt-in) ──
PID=$(node src/main.ts register ai-provider --name qwen-local --custom-provider-id qwen-token-plan \
  --api openai-completions --base-url "$URL" --model qwen-max --allow-insecure \
  --value-file "$D/key.txt" | grep -oE '01[0-9A-HJKMNP-TV-Z]{24}')
[ -n "$PID" ] && echo "PASS A/B: custom openai-compatible provider registered ($PID)" \
  || { echo "FAIL A/B: custom register failed"; exit 1; }

# ── Story C/D — test the model: ask the datetime, print its response ──
node src/main.ts test ai-provider --id "$PID" --prompt "What is today's datetime?" > "$D/test.out" 2>&1
grep -qi 'DATETIME-OK' "$D/test.out" \
  && echo "PASS C/D: test ai-provider reached the custom model and printed its response" \
  || { echo "FAIL C/D: model test did not return the expected response"; cat "$D/test.out"; exit 1; }

# ── leak gate — neither register nor test output leaks the key ──
cat "$D/reg-bad.out" "$D/test.out" > "$D/all.out"
grep -q 'SECRET' "$D/all.out" \
  && { echo "FAIL leak: api key leaked to output"; exit 1; } \
  || echo "PASS leak: no api key in register/test output"

echo "008.1-custom PROOF OK"
```

## Stories

- **A — Custom-provider schema in the registry.** Migration **20** extends
  `ai_providers` (008.1) with nullable `api` (allowlisted:
  `openai-completions` / `openai-responses`), `contextWindow` INTEGER,
  `maxTokens` INTEGER. A record is **custom** iff `api IS NOT NULL`; `provider`
  holds the `--custom-provider-id`, `baseUrl` the endpoint, `model` the model id.
  Extend `GlobalAiProvider` + `AiProviderRegistry` accordingly.
- **B — `register ai-provider` custom path.** When `--api` is given, treat the
  registration as custom: skip pinned-catalog validation (`ModelCatalog.isValid`),
  require `--custom-provider-id` + `--base-url` + `--model`, accept optional
  `--context-window` / `--max-tokens` (documented conservative defaults, e.g.
  32768 / 4096; `cost`=unknown/0, `reasoning`=false, `input`=["text"]). Persist
  the custom record. `--api` must be in the allowlist (else typed error).
- **C — Session reconstruction for custom providers.** In
  `PiProviderSessionFactory` (`src/agent-runner/pi-session.ts`), when the resolved
  provider is custom, build a pi `Model` from the record + defaults, call
  `createProvider({ id: <runtimeId>, name, baseUrl, auth: { apiKey: <static from
folded value> }, models: [model], api: <openAICompletionsApi()|openAIResponsesApi()> })`
  and `models.setProvider(...)` on a **session-local** `MutableModels`, where
  `runtimeId` is derived from the registry **record id** (never the bare
  `--custom-provider-id`) so same-kind accounts do not collide. `getModel(runtimeId,
model)` then resolves. No ambient env-key fallback — the folded value is the
  only key.
- **D — `test ai-provider` CLI + mock fixture.** New `test ai-provider --id <id>
[--prompt <text>]` command: resolve the provider, build a `ProviderSession`, send
  a single-turn completion with the prompt (default "What is today's datetime?"),
  collect the streamed text, print it (stdout) — no agent loop, no workspace. Add
  `scripts/e2e/mock-openai-completions.mjs`: a loopback HTTP server speaking the
  OpenAI `/v1/chat/completions` SSE protocol that streams a reply containing
  `DATETIME-OK` and prints its `http://127.0.0.1:<port>/v1` base URL to stdout.
- **E — Endpoint trust controls.** `register` (custom path) refuses a `--base-url`
  that is plain `http://` or resolves to a private/loopback host unless
  `--allow-insecure` is passed (typed error naming `--allow-insecure`); rejects a
  URL with embedded userinfo (`user:pass@`, reuse `hasEmbeddedUserinfo`); the
  effective endpoint is shown in `get`/`list ai-provider` views (redacted — key
  never shown). Custom endpoints are treated as trusted operator config, not
  SSRF-hardened beyond these guards.

## Non-goals

- No **dynamic** model discovery (`refreshModels`) — models are static/operator-
  supplied.
- No **OAuth** for custom providers — API key only (via `--value-file`); `login`
  stays OAuth-only (008.3).
- No image/embedding models; single `--model` per custom record (repeat register
  for more).
- No full SSRF hardening (DNS-rebinding/redirect defense) — `--allow-insecure` is
  an explicit operator escape hatch, not a security boundary.
- No change to builtin pinned-catalog providers (008.1/008.3) or failover (008.4).
