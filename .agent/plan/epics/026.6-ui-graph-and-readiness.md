## Goal

The operator can read an initiative the way the daemon sees it: one lane per
objective, tasks as nodes inside their lane, dependency edges between them, the
critical path on demand, and a task inspector that is the real task summary
rather than a second one. The graph stays fresh while the tab is visible. A
project's readiness is a page, and the daemon's own `next.command` is the first
real `CommandHandoff` in the product. An initiative's package can be exported.

## Verified facts (measured on this tree, 2026-07-31 — do not re-litigate)

- `GET /api/initiative/:id/graph` returns `initiative`, `groups[]` (objectives,
  with `repositories: string[]`, `commitOid`, `conflictReason`, `after`,
  `waiting`, `action`), `nodes[]` (tasks, each with `groupId`,
  `dependencyState`, `executionState`, `blockedForever`, `downstream`,
  `lastEventId`, `lastEventAtMs`, `candidate`, `action`, and more),
  `edges[] {from,to}`, `criticalPath {metric,nodeIds,length}` and nine `counts`.
- **`groups[].repositories` holds resource IDs, not names** — they come from
  `task_context["repository"]`. Rendering them raw would put ULIDs on screen.
  **[debate]**
- **The graph response has no `digest.latest`.** The freshness signal the design
  document names lives on the project overview, not here. **[debate]**
- **`InitiativeGraphNodeView` is NOT `TaskDetailView`.** The detail has
  `context`, `dependencyStatus`, `abandoning`, the full result shape and a
  different landing-candidate shape; the graph node has `executionState` and
  `lastEventAtMs`, which the detail does not. "Same fields" was wrong.
  **[debate]**
- `criticalPath.metric` is the **longest remaining chain by node count** — not
  duration and not effort. **[debate]**
- The nine `counts` mix mutually exclusive status totals with overlapping
  predicates (`blocked`, `blockedForever`, `actionable`). Rendering all nine as
  one flat row invites false comparison. **[debate]**
- Import is blocked, four ways: `POST /api/project/:id/graph` has **no
  `dryRun`** and creates immediately; `pkg` must be **already-parsed JSON**
  (`parseGraphPackageDocument`), and markdown parsing plus `--bind` resolution
  are CLI-only; request `bindings` are an arbitrary string record the server
  never validates as project-owned resources of the declared type; and tasks
  **created during apply receive no task context**, so "apply to existing"
  cannot bind them. Recorded as `docs/ui-design.md` prerequisite 10. **[debate]**
- `POST /api/graph/readiness` validates a **task DAG only** — ids and
  dependencies, every task treated as pending. It is not package validation.
  **[debate]**
- `GET /api/project/:id/readiness` returns checks with `status`, `blocking`,
  `detail`, optional `probes[]` and `ageSeconds`, plus `next` carrying
  `command`. Both probe flags are hardcoded `false` (`routes.ts:970`), so live
  probing is CLI-only.
- `GET /api/initiative/:id/package` exports the package document.

## Decisions (binding)

1. **Lane = objective; repository chips are resolved names.** The graph adapter
   joins `groups[].repositories` against the project's repository collection and
   renders names; an id with no match renders as an explicit "unknown resource"
   chip, never a bare ULID. A group with **no** repository renders an explicit
   **"no repository binding"** lane state — not blank space, because for
   `generic@1` and `tdd@1` that condition can mean the graph cannot run.
   **[debate]**
2. **The layout is specified, not left to the library.** Lanes are ordered by
   the objective order the API returns; nodes inside a lane are ordered by
   dependency depth, then by id; edges route between lanes; a lane taller than
   the viewport scrolls within the canvas. The canvas emits an application-owned
   **`layout-ready`** state after measurement and `fitView`, which is what the
   Proof waits for. **[debate]**
3. **The canvas is read-only, and the write path is one click away.** No
   drag-to-create, no edge editing, nodes are not draggable. Selecting a node
   opens the inspector; the inspector links to the canonical task page, where
   026.4's dependency editing lives. **[debate]**
4. **The inspector fetches `GET /api/task/:id` and reuses the real Summary
   component.** Two summaries would drift, and the graph node genuinely lacks
   fields the summary shows. Selection therefore has its own loading, error and
   missing states. **[debate]**
5. **Counts are split, not flattened.** Six lifecycle totals render as one
   group; `blocked`, `blockedForever` and `actionable` render as a separate
   "operational" group, because they overlap the totals. **[debate]**
6. **The critical path is a toggle, off by default, and names its metric** —
   "longest remaining chain, by task count", which is the operator wording for
   the one metric the API sends today, `metric: "remaining-node-count"`
   (`src/domain/graph.ts:221`). A hermetic test pins that pairing, so a new
   metric value fails loudly instead of shipping a wrong label. It highlights
   the ordered path's **edges as well as its nodes**. **[debate]**
7. **Freshness: the graph polls the overview as its signal.** `digest.latest`
   does not exist on the graph response, so the visible graph polls
   `["project", id, "overview"]` with the 026.2 engine and refetches
   `["initiative", id, "graph"]` only when `latest` changes. Hierarchy
   mutations invalidate the graph key **immediately**, without waiting for a
   poll. Both rows are added to the invalidation matrix. **[debate]**
8. **Readiness is read-only, and each route is described for what it is.** The
   project readiness page lists checks by `status` and `blocking`, and renders
   `next.command` through CommandHandoff. Live probing is named as unavailable
   over HTTP with the CLI command offered — and that command is **built for the
   probe flags**, not assumed to be `next.command`. `POST /api/graph/readiness`
   is used only where a task DAG is what is being checked, and is never
   labelled "package validation". The page renders the `next.command` handoff
   **before** the live-probe handoff, so the Proof's first `command-handoff` is
   always the daemon's own command. **[debate]**
9. **Export is a download of `GET /api/initiative/:id/package`** — no editing,
   no round-trip, because applying it back is import, and import is 026.15's.
10. **The graph's URL carries its initiative.** A graph is per-initiative, but
    ProjectShell's settled nav has a project-level `Graph` item. So the
    canonical route is `#/project/:projectId/initiative/:initiativeId/graph`,
    and the nav's `#/project/:id/graph` renders an initiative **picker** when
    the project has more than one, or redirects when it has exactly one. Scope
    still comes from the URL; a query parameter would have hidden it.
11. **The Plan tab renders an explicit unavailable state**, naming all four
    blocking gaps in operator language and offering the CLI import command
    through CommandHandoff. It is not a disabled button and not a blank page.

## Verification Gate

Gates: `npm run verify`.

Hermetic coverage required beyond the Proof (Vitest + jsdom, in `ui/`):

- **The graph adapter**: DTO → lanes/nodes/edges; a repository id with no match
  renders "unknown resource" (the Proof covers the resolved-name and
  no-binding cases, not this one); a group with no repositories renders
  `lane-no-repository`; node order is dependency depth then id.
- **The inspector** (decision 4): selection triggers `GET /api/task/:id`; its
  loading, error and missing states each render; the component rendered is the
  same one the task page's Summary uses.
- **Counts** (decision 5) render in two groups, never one row.
- **Critical path** (decision 6): the toggle is off by default, marks the
  ordered edges as well as the nodes, and the label names the metric — pinned
  to the API value `remaining-node-count`.
- **Export** (decision 9): the download body is the unwrapped package DTO, the
  filename is exact, and the object URL is revoked. The Proof does not cover
  export.
- **Freshness** (decision 7): an unchanged `digest.latest` refetches no graph; a
  changed one refetches exactly the graph key; a hierarchy mutation invalidates
  the graph key without a poll.
- **Readiness**: blocking and non-blocking checks render distinctly;
  `next.command` renders verbatim in CommandHandoff; the probe handoff command
  is built with the probe flags and is not `next.command`.
- **Plan unavailable** (decision 11) names all four gaps and is not a disabled
  button.
- **The graph route** (decision 10): the nav-level URL redirects when the
  project has one initiative and renders the picker when it has more.

  blocked by four API gaps, now `docs/ui-design.md` prerequisite 10, and built
  in EPIC 026.15. W5 StagedWorkflow therefore has no instance until then.
- **No graph editing.** Dependency edits stay in 026.4's forms.
- **No live probing** — the flags are hardcoded `false`; the CLI keeps it.
- **No package editing in the browser.** Export downloads; it does not round-trip.
