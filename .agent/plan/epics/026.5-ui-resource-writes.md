# EPIC 026.5 — resource writes: four schemas, credential rotation, honest remote changes

> Authored 2026-07-31. The design went through the debate engine (`pi`,
> read-only). Eleven findings changed the shape and are marked **[debate]**.
> Two were factual corrections verified against this tree: the API **rejects a
> blank string** where the draft wanted to send `path: ""`, and **`reclone` does
> no git work at all** — it is a confirmation that the cached local home may be
> discarded when the remote URL changes. A UI control labelled "Reclone" would
> have been a lie.
>
> Execution order: 026 → … → 026.4 → **026.5** → 026.6 → 026.7 → 026.8.
> Normal `/work`: writes only `ui/**` and `scripts/**`, installs nothing
> (EPIC 026 decision 9), adds no API route.

## Goal

The operator can add and maintain a project's resources from the browser:
repositories, credentials, notifications and filesystems, each through its own
form built from its own schema. A credential's secret can be rotated without the
UI ever reading it back or folding it into the conflict machinery. What the API
actually does is what the screen says it does — including the remote-URL change
that discards a cached home, which is named for what it is.

## Verified facts (measured on this tree, 2026-07-31 — do not re-litigate)

- **A blank string is rejected**, not treated as absent: `requireBodyString`
  trims and throws `must not be blank` (`body.ts:20-30`), and
  `optionalBodyString` delegates to it. So the UI **omits** an optional field
  it has no value for; it never sends `""`. The draft's "send an empty path to
  derive it" was wrong. **[debate]**
- **`reclone` performs no git work.** `UpdateRepository`
  (`src/app/resource/update-repository.ts:48-70`) only consults it while
  `remoteUrl` changes: if the stored home path exists and `reclone` is not set,
  it throws `CacheConflictError`; if it is set, the stored `path` becomes `""`.
  Nothing is deleted, fetched or cloned. A PATCH of `{reclone:true}` alone is a
  no-op. **[debate]**
- Create bodies: repository `name, remoteUrl, branch, path?, auth`; credential
  `name, provider, value`; notification `name, provider` (**`slack` or
  `telegram` only**), `destination`; filesystem `name, path`.
- Patch bodies: repository `name, branch, path, remoteUrl, auth, reclone`;
  credential `name, value`; notification `name, destination`; filesystem
  `name, path`. Each also takes an optional `type` probe.
- `provider` is create-only for credential and notification; `auth` is required
  on create and optional on patch. **Create and edit are different schemas, not
  one schema with two buttons.** **[debate]**
- `auth` is discriminated (`body.ts:128-150`): `{kind:"ambient"}`,
  `{kind:"ssh-agent"}`, `{kind:"https-token", credentialId}`. The server does
  **not** verify that `credentialId` exists, is a credential, or belongs to the
  project. **[debate]**
- Every resource PATCH declares `readRow: "resource.get"`, and
  **`resourceView` omits the credential `value`** — so a value-only rotation can
  leave the `ETag` unchanged. Credential rotation therefore cannot participate
  honestly in the 026.4 conditional-edit layer. **[debate]**
- `IMMUTABLE_FIELDS` are enforced by the use case, but `type` in the body is
  optional in every decoder, so the probe is a **client-side defence**, not a
  server invariant. **[debate]**
- `publication` is `{state, remoteOID} | null`; `null`, `unpublished`,
  `published` and `diverged` are four distinct states. **[debate]**
- Resource names are checked **project-wide**, not per type.
- There is **no delete route** for any resource, and no land/publish route.
- `app.ts:113` logs method, path and status — never a request body.

## Decisions (binding)

1. **Four resource modules, each with a separate create builder and edit
   builder.** They share only the 026.4 edit-session layer, field-error mapping
   and the invalidation matrix. Create-only fields (`provider`) never appear in
   an edit payload; an optional field with no value is **omitted, never
   `""`**. **[debate]**
2. **Credential metadata and credential rotation are two different flows.**
   Renaming a credential is an ordinary 026.4 edit session. **Rotating the
   secret is a separate, ephemeral control with its own submit path**: the value
   never enters `{baseData, baseEtag, draft}`, never enters the three-version
   conflict state, and is **never replayed automatically after a `412`**. There
   is no server-side base value to compare against, so pretending otherwise
   would be theatre. **[debate]**
3. **The secret boundary is stated at its true scope**: the value is _not
   returned by the resource read APIs_, and the UI keeps it out of every store
   it owns — query data, query keys, mutation keys, mutation-cache variables
   after settlement, and any persisted storage. It is **not** a claim about
   browser memory, devtools, request inspection, or storage at rest.
   Playwright tracing, video and screenshots are **disabled for the rotation
   scenario**, so the Proof cannot become the leak. **[debate]**
4. **Retention after a failed rotation is per failure kind**, not one blanket
   rule: **[debate]**
   - client-side validation error → keep the typed value
   - definite server rejection (4xx with a code) → keep it, show the code
   - `412` → keep it **only** inside the isolated rotation control, and require
     an explicit resubmit after a refresh
   - ambiguous transport failure → keep it and say plainly that the rotation
     **may already have succeeded**
   - success, cancel, navigation, unmount → clear it
   - an explicit **Clear** control is always available
5. **Rotation success and rotation concurrency are not observable today.**
   The credential DTO exposes nothing that changes when the value changes, so
   the UI cannot confirm a rotation landed, and two rotations cannot conflict.
   This epic **does not pretend to**: it reports the HTTP result and no more.
   A non-secret `secretRevision` (or `valueUpdatedAt`) on the credential view is
   added to the 026.8 gap list. **[debate]**
6. **Repository auth is a discriminated control**, and the guarantee is named
   accurately: choosing `https-token` reveals a picker over the project's
   credential collection, which yields "a well-shaped reference chosen from the
   credentials this project can see" — **not** a validated reference. Server-side
   validation of `auth.credentialId` goes on the 026.8 gap list. The UI never
   sends a partial auth object and invents no provider-compatibility rule.
   **[debate]**
7. **There is no "Reclone" control.** The real operation is **"Change remote
   URL"**, and `reclone` is its confirmation step: when the server answers
   `CacheConflictError`, the UI explains that a cached local home already exists
   for this repository and that continuing **discards the stored home pointer**
   — then resubmits the same `remoteUrl` with `reclone: true`. DangerConfirm
   guards that continuation. The UI never sends `reclone` on its own, and never
   claims a clone, a fetch or a deletion happened. A real reclone would be a new
   server operation. **[debate]**
8. **The `type` probe is sent on every patch, and described as what it is** — a
   defence against this client hitting the wrong typed endpoint, not an
   endpoint-level invariant. Server-side type enforcement per route joins the
   026.8 gap list. **[debate]**
9. **Publication renders all four states**: `null` (no publication record),
   `unpublished`, `published@<oid>`, and `diverged` — never collapsing `null`
   into `unpublished`. It is read-only; land and publish need Target 024 and
   appear only where a real CLI handoff exists. **[debate]**
10. **Create is on the typed collection tab; edit is on the resource page.**
    Because **no resource can ever be deleted**, the create form states that
    before submit, marks the create-only fields, and warns that the name must be
    unique **across the whole project**, not within the type. On success the UI
    navigates to the new resource's page. **[debate]**

## Verification Gate

Gates: `npm run verify`.

Hermetic coverage required beyond the Proof (Vitest + jsdom, in `ui/`):

- **Payload builders**: an optional field with no value is omitted, never `""`;
  `provider` never appears in an edit payload; `auth` is complete or absent;
  `type` is always present on a patch.
- **The secret's owned-state boundary** (decision 3), with a sentinel value:
  after settle, the sentinel appears in no query cache entry, no query key, no
  mutation key, no mutation-cache variables, and no persisted storage; a
  captured logger sees it on neither the success nor the failure path.
- **Retention per failure kind** (decision 4), one case each, plus Clear.
- **Rotation never touches conflict state** (decision 2): a stubbed `412` on a
  metadata edit does not carry, replay or reveal a secret.
- **The remote-URL flow** (decision 7): a stubbed `CacheConflictError` renders
  the confirmation naming the discarded home pointer; only the confirmation
  sends `reclone: true`, and it resends the same `remoteUrl`; nothing sends
  `reclone` alone.
- **Publication**: all four states render distinctly (decision 9).
- **Notification provider** accepts only `slack` and `telegram`.

Proof: `scripts/e2e/ui-resources-proof.sh` — deterministic, no model, loopback
only, nothing left running. **Playwright tracing, video and screenshots stay
off** (decision 3):

```bash
scripts/e2e/ui-resources-proof.sh
```

It must print `026.5 ok: …`. Phases:

- **A** — build the UI; Chromium present, or exit with the install command.
- **B** — seed a project; start the daemon on the build.
- **C** — create a credential **through the UI**; the API confirms it exists and
  **no read response anywhere contains the secret**; the rotation input is
  empty after success.
- **D** — create a repository through the UI with `auth.kind = https-token`,
  picking the credential from C; the request body carries a **complete** auth
  object and no blank string; the API confirms the stored auth.
- **E** — rotate the secret through the isolated control; the PATCH is `200`;
  the credential detail still exposes no value; the input is cleared. The Proof
  **does not** claim the new value was stored — decision 5 says the API cannot
  show that.
- **F** — the honest remote change: patch `remoteUrl` while a home path exists,
  get the cache conflict, see the confirmation naming the discarded home
  pointer, continue, and verify through the API that `path` is now empty — and
  **nothing more**, because nothing more happens.
- **G** — publication renders its state, and R3 holds: no request the page
  issued carried an `Authorization` header.

Ran against the CURRENT tree (2026-07-31): the script exits `1` in phase A,
because `ui/` does not exist and `npm run build:ui` is not a script yet.

## Stories

- **S1 — the four payload builders** (decision 1) and their tests.
- **S2 — credential create + metadata edit**, no secret in the session layer.
- **S3 — the isolated rotation control** (decisions 2–4).
- **S4 — repository create/edit + the discriminated auth control** (decision 6).
- **S5 — the "Change remote URL" flow and its confirmation** (decision 7).
- **S6 — notification + filesystem** forms.
- **S7 — publication's four states** (decision 9) and the permanence notice.
- **S8 — the Proof**: `scripts/e2e/ui-resources-proof.sh` prints `026.5 ok: …`
  without its assertions being edited.

## Non-goals

- **No "Reclone" operation** (decision 7). A real one is a server epic.
- **No claim that a rotation landed**, and no rotation concurrency (decision 5).
- **No validation of `auth.credentialId`** beyond picking from the project's own
  credentials (decision 6).
- **No resource delete** — no route exists.
- **No land, no publish** — Target 024, listed for 026.8.
- **No secrecy claim about browser memory, devtools or storage at rest**
  (decision 3).
