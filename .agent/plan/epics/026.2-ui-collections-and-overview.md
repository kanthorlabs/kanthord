## Goal

The operator can see real project state in the browser. Three read surfaces
work against live data: the Projects collection (W1), the project Overview
composition, and the Resources collection (W1) with its four typed tabs
addressable in the URL. The Overview stays fresh by itself — one polling engine,
visibility-gated, driven by `digest.latest` — so an event produced by the daemon
appears on screen with no click. Nothing on these screens writes: EPIC 026.4
and 026.5 own every mutation.

## Verified facts (measured on this tree, 2026-07-30 — do not re-litigate)

- Reads available: `GET /api/project`, `/api/project/:id`,
  `/api/project/:id/overview`, `/api/project/:id/initiative`,
  `/api/initiative/:id`, `/api/initiative/:id/objective`,
  `/api/initiative/:id/task` (`?status=`, `?objective=`), `/api/objective/:id`,
  `/api/task/:id`, `/api/resource/:id`.
- **There is no unified resource list.** Resources are four separate collections
  built by `resourceCollectionRoute` (`src/apps/http/routes.ts:142`):
  `GET /api/project/:id/{repository,credential,notification,filesystem}`, each
  taking an optional `?name=`. A merged table would have to invent a row
  grammar the API does not have. **[debate]**
- The four resource DTOs really do differ (`views/resource.ts`): `repository`
  carries `remoteUrl`, `branch`, `path`, `auth`, `publication {state,
remoteOID}`; `credential` carries `provider`; `notification` carries
  `provider` + `destination`; `filesystem` carries `path`.
- `projectOverviewView` (`views/project.ts:25`) returns `initiatives[]
{id,name,status,paused,taskCounts{6},needsHuman,action}`, `lanes[]`,
  `decisions[] {action,initiativeId,objectiveId,taskId,downstream,
actionableSince}` and `digest {since,latest,totalCount,byType,events,hasMore,
pageCursor}`.
- `digest.latest` is the newest project event id and moves independently of the
  ack, so it is a valid change signal. `POST /api/objective/:id/task` appends
  `task.created` (`src/app/task/create-task.ts:121`), which is how the Proof
  creates a real change while the page is open.
- `digest.hasMore` can be true and **the client cannot page it**:
  `routes.ts:287` decodes the path param only. Paging is EPIC 026.8. **[debate]**
- Queue items have no id, so a decision row cannot deep-link to a decision.
  Decisions carry `initiativeId`, `objectiveId`, `taskId`, so they can link to
  the entity they concern. **[debate]**
- `PATCH` requires `If-Match` and answers `428` without it (`app.ts:235`,
  `error-registry.ts:142`). This epic writes nothing, so it captures no `ETag`;
  that contract belongs to EPIC 026.4. **[debate]**
- ProjectShell's settled nav is `Overview`, `Graph`, `Plan`, `Resources`,
  `Readiness` — **there is no Initiatives nav item**, though the template table
  listed Initiatives under W1. Resolved by decision 7. **[debate]**

## Decisions (binding)

1. **Resources is one screen with four URL-addressable typed tabs:**
   `#/project/:id/resource/:type`, `:type` ∈ `repository | credential |
notification | filesystem`. The tab is identity, not local state, so reload,
   deep link and browser history all keep the collection. `#/project/:id/
resource` redirects to `…/repository`. An unknown `:type` renders
   AsyncBoundary `missing`, never a silent fallback to the first tab.
   **[debate]**
2. **One query per tab, and only the visible tab runs.** A tab already loaded
   stays in the cache when the operator switches away; a hidden tab is never
   refetched and never polled. **[debate]**
3. **Search is server-side and type-local.** The toolbar sends `?name=` to the
   active collection only, and its placeholder names the scope
   ("search repositories"), so it cannot read as cross-resource search.
   **[debate]**
4. **Overview is the approved composition** (`docs/ui-design.md` § Templates,
   Ulrich 2026-07-30) inside ProjectShell, in this fixed order: initiative
   summary cards (StatusChip + the six task counts + `needsHuman`), the
   decisions list, the digest head window. **Lanes are not rendered here** —
   they are the graph's, and the Overview links to `…/graph` so the omission is
   visible rather than silent. **[debate]**
5. **`digest.hasMore === true` renders AsyncBoundary's `truncated` state**,
   naming that this is the head window and that paging arrives with EPIC 026.8.
   A truncated digest is never shown as if it were the whole history.
   **[debate]**
6. **Decision rows link to the entity, never to a decision.** Each row links to
   the task, objective or initiative it names, and carries no act control:
   approve/reject/retry live in EPIC 026.8, and until then a decision row is
   evidence plus a `CommandHandoff` when the CLI has an equivalent. Queue items
   have no id, so no row may claim a decision deep link. **[debate]**
7. **There is no Initiatives screen.** The initiative collection surface is the
   Overview's initiative cards, plus the graph in 026.6. Adding a route with no
   nav entry would contradict the settled ProjectShell nav.
   `docs/ui-design.md`'s W1 "Used by" column is corrected to
   `Inbox, Projects, Resources` in the same change. **[debate]**
8. **No write control appears on these screens — and their absence is not a
   disabled state.** `docs/ui-design.md`'s disabled-control rule covers controls
   whose API route is missing. Create and rename routes exist; they are merely
   unbuilt until EPIC 026.4, and an unbuilt control is omitted, not greyed out.
   Confusing the two would tell the operator the API cannot do something it can.
9. **Detail panes are read-only here.** A W1 row opens a pane showing the row's
   own DTO plus, for a resource, `GET /api/resource/:id`. No pane captures an
   `ETag`, because nothing in this epic can PATCH. **[debate]**
10. **One polling engine, with an explicit contract.** `useVisibilityPoll` lives
    in `ui/src/lib/polling.ts` and is written to be reused by the graph in
    026.6. Binding behaviour, all of it testable: **[debate]**
    - polls only while `document.visibilityState === "visible"`; stops on hidden
    - refetches **immediately** when the tab becomes visible again
    - never overlaps: a poll in flight suppresses the next tick
    - aborts on unmount and on project change
    - the signal is `digest.latest`; `null → ULID` counts as a change, and an
      unchanged `latest` performs no invalidation
    - a failed poll leaves the last `Updated HH:MM` intact and surfaces the
      error without clearing the screen
    - manual refresh works independently and is never disabled by polling
    - interval is one named constant, `POLL_INTERVAL_MS = 15_000`, in that module
11. **The query-key hierarchy is fixed here, and invalidation is narrow.**
    `["project"]`, `["project", id]`, `["project", id, "overview"]`,
    `["project", id, "resource", type]`, `["resource", id]`. A `digest.latest`
    change invalidates **`["project", id, "overview"]` only** — never the
    resource collections, which no task event can affect. "Invalidate the
    project's queries" was too broad. **[debate]**

## Verification Gate

Gates: `npm run verify`.

Hermetic coverage required beyond the Proof (Vitest + jsdom, in `ui/`):

- **Polling**, all nine bullets of decision 10, with fake timers and a stubbed
  `visibilityState`: hidden stops it, visible resumes and refetches at once,
  an in-flight poll suppresses the tick, unmount aborts, an unchanged `latest`
  invalidates nothing, a changed `latest` invalidates exactly the overview key,
  a failed poll keeps the previous `updatedAt`.
- **Query keys**: the invalidation of decision 11 touches the overview key and
  leaves every resource key untouched — asserted on the cache, not by reading
  the code.
- **Resource tabs**: each type renders its own columns; the repository row shows
  `branch` and `published@<oid>` built from `{state, remoteOID}`; an unknown
  type renders `missing`; a cached tab is not refetched on return.
- **Overview**: the three sections render in the fixed order of decision 4;
  `hasMore` renders `truncated`; a decision row links to its task/objective/
  initiative and renders no act control; an empty project renders `empty`, not
  an error.
- **Search** sends `?name=` on the active collection only and does not filter
  client-side.
- **No write control** is rendered by any screen in this epic (decision 8).

Proof: `scripts/e2e/ui-collections-proof.sh` — deterministic, no model, loopback
only, nothing left running:

```bash
scripts/e2e/ui-collections-proof.sh
```

It must print `026.2 ok: …`. Phases:

- **A** — build the UI; Chromium present, or exit with the install command.
- **B** — seed through the real API: one project, two initiatives, one objective
  with two tasks, one repository and one credential resource.
- **C** — `#/project` renders both seeded projects; typing in the toolbar search
  issues a request whose URL carries `?name=`, and the table narrows.
- **D** — the project's Overview renders one card per initiative with the real
  names, the six counts matching the seeded tasks, the decisions section and the
  digest section, in that order.
- **E** — `#/project/:id/resource/credential` **cold-loaded** renders the
  credential grammar; switching to the repository tab changes the URL and shows
  the `branch` column; reloading that URL keeps the repository tab; an unknown
  type renders the missing state.
- **F** — the polling engine, the load-bearing phase: with the Overview open and
  untouched, a **new task is created through the API**, and the card's pending
  count rises on screen with no user interaction, inside two poll intervals.
- **G** — R3 still holds: no request the page issued carried an `Authorization`
  header.

Ran against the CURRENT tree (2026-07-30): the script exits `1` in phase A,
because `ui/` does not exist and `npm run build:ui` is not a script yet.

## Stories

- **S1 — query keys + `api-client` list helpers** (decision 11).
- **S2 — Projects W1**: table, server-side `?name=` search, read-only pane.
- **S3 — Overview composition**: cards, decisions, digest, truncated state.
- **S4 — the polling engine** (`ui/src/lib/polling.ts`, decision 10) and its
  hermetic tests, wired to Overview only.
- **S5 — Resources W1**: the typed tab route, four row grammars, unknown type.
- **S6 — the Proof**: `scripts/e2e/ui-collections-proof.sh` prints `026.2 ok: …`
  without its assertions being edited.

## Non-goals

- **No writes at all** — no create, no rename, no resource edit, no `If-Match`,
  no secret handling. EPIC 026.4 and 026.5.
- **No entity workspace.** A row opens a read-only pane; the W2 pages and their
  nested canonical routes are EPIC 026.3's.
- **No lanes, no graph, no import, no readiness** — EPIC 026.6.
- **No inbox and no conflict** — EPIC 026.7.
- **No digest paging, no decision deep link, no act control** — EPIC 026.8.
- **No `⌘K` palette.**
