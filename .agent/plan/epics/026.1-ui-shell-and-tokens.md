# EPIC 026.1 — UI shell + token system: two shells, hash routes, six roles, five shared parts

> Authored 2026-07-30. The design went through the debate engine (`pi`,
> read-only). Nine findings changed the shape and are marked **[debate]**
> inline. Two of them were escalated to Ulrich and are settled in EPIC 026
> decisions 9 and 10 — dependencies and the browser Proof — because they bind
> every UI epic, not only this one.
>
> Execution order: 026 → **026.1** → 026.2 → … → 026.7 → 026.8.
> This is a normal `/work` epic: it writes only `ui/**` and `scripts/**`.
> It installs nothing (EPIC 026 decision 9) and adds no API route.

## Goal

The dashboard has a body. Both shells from `docs/ui-design.md` render for real:
GlobalShell (nav `Inbox`, `Projects`, `Operations`; header freshness slot) and
ProjectShell (nav `Overview`, `Graph`, `Plan`, `Resources`, `Readiness`; header
breadcrumb). Hash routing carries the whole scope, so a deep link opened cold in
a browser lands on the right screen inside the right shell. The six operator
roles exist once as CSS custom properties and once as an exhaustive TypeScript
mapping, so no component can invent a colour. The five shared parts exist with
the contracts the design document fixes. One real screen — Operations, holding
the health card that EPIC 026 left loose — proves the whole stack end to end in
a real browser: query → transport seam → AsyncBoundary → FreshnessBar → shell.

## Verified facts (measured 2026-07-30 — do not re-litigate)

- **jsdom cannot execute a Vite build.** jsdom does not run
  `<script type="module">`; a Vite 8 build emits exactly that tag, and EPIC 026
  Proof phase B asserts it does. A jsdom-based Proof would load the served page,
  execute nothing, and assert against an empty `#root`. This killed the first
  draft's Proof mechanism. **[debate]**
- Vitest + jsdom is unaffected by that limit: Vite transforms modules before
  jsdom sees them. jsdom stays the right tool for the workspace's unit tests and
  the wrong tool for the Proof.
- `GET /healthz` returns `{status, version}` only (`src/apps/http/routes.ts:236`).
  There is no last-ping and no processed-today field; the dead-man card is EPIC
  026.8. The version string is real and is what the Proof compares against.
- `GET /api/project` (`routes.ts:255`) and `GET /api/project/:id`
  (`routes.ts:270`) exist, so a real project id and name are available to the
  Proof for the ProjectShell breadcrumb.
- `docs/ui-design.md` names the enum axes the token layer must cover: task
  status, initiative status, `dependencyState`, `executionState`,
  `blockedForever`, readiness check status, probe status. It also states that
  **publication is a label, not a token value**. The first draft's inventory
  missed `blockedForever` and publication. **[debate]**
- `docs/ui-design.md` assigns "the five shared parts" to this epic. That is the
  settled roadmap, and AGENTS.md forbids weakening a binding directive
  silently. **[debate]**
- Queue items have no id today, so `/#/inbox/:itemId` is not implementable.
  No epic may register it before EPIC 026.8.

## Decisions (binding)

1. **The Proof drives a real browser** — EPIC 026 decision 10. This epic writes
   the shared helper `scripts/e2e/ui-browser.mjs`: it launches Playwright's
   pinned Chromium headless, sets `httpCredentials` for the Basic gate, exposes
   `goto(hash)`, `text(selector)`, `count(selector)` and a console-error
   collector, and **fails with the exact `npx playwright install chromium`
   command** when the browser is absent. Every later UI epic reuses it.
2. **TanStack Query is adopted here, with one real consumer.** The health card
   moves out of EPIC 026's loose page into the Operations screen and becomes a
   query. That gives Query, AsyncBoundary and FreshnessBar a genuine consumer in
   this epic rather than three components with none. **[debate]**
   `ui/src/lib/api-client.ts` stays the only module that calls `fetch` (R3);
   Query orchestrates it and never fetches itself.
3. **AsyncBoundary is presentational, over its own union** —
   `{state: "loading" | "empty" | "error" | "missing" | "resolved" | "expired" |
"truncated"}`. It is NOT coupled to Query's status enum: `expired` and
   `truncated` are domain states from the decision queue and arrive in 026.7.
   Adapters map a query result into the union; the component only renders.
   **[debate]**
4. **Only settled top-level routes are registered.** `#/inbox`, `#/project`,
   `#/operations` in GlobalShell; `#/project/:id/overview`, `…/graph`, `…/plan`,
   `…/resource`, `…/readiness` in ProjectShell. **No parameterized deep link
   beyond the project `:id`** — entity detail, import, conflict and queue-item
   paths are defined by the epic that builds them. `/#/inbox/:itemId` is
   forbidden until 026.8 gives queue items an id. **[debate]**
5. **Placeholders are an honest unavailable state, not progress theatre.** Every
   leaf this epic does not build renders one shared `NotBuiltYet` component that
   names its owning epic in the text. A test asserts each registered leaf either
   renders real content or renders `NotBuiltYet`; there is no third option, and
   no leaf renders blank. **[debate]**
6. **`#/` redirects to `#/inbox`**, the final shape, even though 026.7 owns that
   screen and it shows `NotBuiltYet` in the interim. Landing on the real default
   now costs one placeholder view and saves a routing change later.
7. **The token layer is exhaustive by type.** Six roles as custom properties in
   the Tailwind v4 `@theme` block; `ui/src/lib/status-role.ts` maps each axis
   listed in the verified facts with `satisfies Record<…, Role>`, so adding a
   union member without a role fails `npm run ui:typecheck`. Publication renders
   as the label `published@<oid>` built from `{state, remoteOID}` and takes no
   role value.
8. **Backend/UI enum drift is explicitly OUT of scope, and recorded as a known
   limit.** Decision 7 enforces exhaustiveness over the UI's own copy of each
   union. A backend that adds a task status does not break the UI typecheck. The
   debate's proposed fix — scraping `src/apps/http/views/*.ts` — is rejected: it
   couples a test to source spelling and still does not prove the wire shape. A
   shared contract or generated schema is separate scope and gets its own epic
   if it is ever wanted. **[debate]**
9. **FreshnessBar is prop-driven and owns no clock.** Contract: required
   `updatedAt: Date | null` (`null` renders an explicit "not updated yet", never
   a blank), required `onRefresh`, and a `refreshing` state that disables the
   control. Visibility-gated polling on `digest.latest` is 026.2's, with the
   overview screen as its first consumer. **[debate]**
10. **All five shared parts land here, with minimal contracts.** StatusChip,
    AsyncBoundary and FreshnessBar get a real consumer through Operations.
    **DangerConfirm has no consumer until 026.4 (dependency removal) and
    CommandHandoff none until 026.3 (a task's disabled action hands over a CLI
    command)** —
    stated plainly as an accepted cost of the binding roadmap, not hidden. Their
    props come only from `docs/ui-design.md`; no variant, no option and no
    generalisation is added before a consumer asks for it. **[debate]**

### Contract with the Proof (binding names)

The Proof and its browser driver are already written and already failing, so
these names are fixed — the implementation must use exactly these, not
equivalents:

| Selector                            | Meaning                                                |
| ----------------------------------- | ------------------------------------------------------ |
| `[data-testid="global-shell"]`      | GlobalShell frame is mounted                           |
| `[data-testid="global-nav"] a`      | its nav links — exactly 3                              |
| `[data-testid="project-shell"]`     | ProjectShell frame is mounted                          |
| `[data-testid="project-nav"] a`     | its nav links — exactly 5                              |
| `[data-testid="breadcrumb"]`        | the ProjectShell breadcrumb text                       |
| `[data-testid="health-version"]`    | the version string on the Operations health card       |
| `[data-testid="freshness-updated"]` | FreshnessBar's `Updated HH:MM` / "not updated yet"     |
| `[data-testid="freshness-refresh"]` | FreshnessBar's refresh control                         |
| `[data-testid="not-built-yet"]`     | the placeholder of decision 5; its text names its epic |
| `[data-testid="async-missing"]`     | AsyncBoundary's `missing` state                        |

The six role custom properties are named `--role-neutral`, `--role-active`,
`--role-attention`, `--role-blocked`, `--role-danger`, `--role-success`, and
resolve on `document.documentElement`.

The browser driver is `scripts/e2e/ui-browser.mjs` (already written): it takes
`--base`, `--key` and `--script`, and the step script default-exports
`async ({ page, goto, text, count, visible, consoleErrors, requests })`.

## Verification Gate

Gates: `npm run verify` — backend typecheck + backend tests + `verify:handoff` +
backend lint + UI typecheck + UI lint + UI tests + UI build + `db status`.

Hermetic coverage required beyond the Proof (Vitest + jsdom, in `ui/`):

- **Token exhaustiveness**: `status-role.ts` compiles under `satisfies` for every
  axis in the verified facts; a test asserts each of the six roles resolves to a
  non-empty CSS custom property name, and that `publication` is absent from the
  role map and renders as `published@<oid>`.
- **StatusChip**: every mapped enum value renders its role class, its domain
  label and its icon. Label and icon carry the domain specificity, not colour.
- **AsyncBoundary**: all seven union states render a distinct, non-blank output;
  `empty` is not styled as an error; `missing` renders an explicit state and
  renders no redirect.
- **FreshnessBar**: `updatedAt: null` renders "not updated yet"; a Date renders
  `Updated HH:MM`; `onRefresh` fires once per click; `refreshing` disables it.
- **CommandHandoff**: renders the command verbatim in a copyable element and
  says the action leaves the browser. **DangerConfirm**: requires an explicit
  confirm step and is never rendered as a visual sibling of a benign action.
- **Shells**: GlobalShell renders exactly the three nav items, ProjectShell
  exactly the five; the mobile Sheet toggle carries the pending indicator; the
  breadcrumb renders the segments it is given and nothing else.
- **Routing**: every registered route resolves to real content or to
  `NotBuiltYet` (decision 5); an unknown hash renders AsyncBoundary `missing`;
  `#/` redirects to `#/inbox`; no test may register `/#/inbox/:itemId`.
- **Transport**: the Operations query goes through `api-client.ts`, and no
  request carries an `Authorization` header (R3) in either `apiBaseUrl` mode.

Proof: `scripts/e2e/ui-system-proof.sh` — deterministic, no model, no outbound
network (loopback only, Chromium pre-installed), nothing left running:

```bash
scripts/e2e/ui-system-proof.sh
```

It must print `026.1 ok: …`. Phases:

- **A** — build: `npm run build:ui` produces `ui/dist/index.html`; Chromium is
  present, or the script exits with the exact install command.
- **B** — the daemon serves that build; Chromium opens `/` with Basic
  credentials; `#/` lands on `#/inbox`; GlobalShell renders exactly `Inbox`,
  `Projects`, `Operations`; the console reports no error.
- **C** — `#/operations` renders the health card with the version string that
  `node src/main.ts --version` prints; FreshnessBar shows `Updated HH:MM`;
  clicking refresh issues a second `GET /healthz`, counted in the daemon log.
- **D** — a project is created through the API; a **cold load** of
  `#/project/<id>/overview` (a fresh page load at that hash, not a client-side
  navigation) renders ProjectShell's five nav items and the breadcrumb with the
  real project name, and the leaf renders `NotBuiltYet` naming EPIC 026.2.
- **E** — an unknown hash renders the missing state and not a blank page;
  `GET /nope` still answers `404 unknown_route`.
- **F** — the token layer is live in the browser: all six role custom properties
  resolve to non-empty values on `document.documentElement`.
- **G** — R3 holds over the wire: no request the page issued carried an
  `Authorization` header, and the API key appears in no response body.

Ran against the CURRENT tree (2026-07-30): the script exits `1` in phase A,
because `ui/` does not exist and `npm run build:ui` is not a script yet — the
same first failure EPIC 026 will clear.

## Stories

- **S1 — tokens.** The `@theme` role properties, `ui/src/lib/status-role.ts`
  with every axis, publication as a label, and the exhaustiveness tests.
- **S2 — StatusChip** over S1's map, with label and icon per domain value.
- **S3 — the two shells.** GlobalShell, ProjectShell, mobile Sheet with the
  pending indicator, breadcrumb.
- **S4 — the hash route table** (decision 4), `NotBuiltYet` (decision 5), the
  `#/` redirect, and the missing-hash state.
- **S5 — query layer + AsyncBoundary.** TanStack Query provider over
  `api-client.ts`, the seven-state union, and the adapters.
- **S6 — Operations screen.** The health card as a real query, wired to
  AsyncBoundary and to FreshnessBar's contract (decision 9).
- **S7 — CommandHandoff + DangerConfirm**, minimal contracts, no consumer yet
  (decision 10).
- **S8 — the Proof.** `scripts/e2e/ui-browser.mjs` and
  `scripts/e2e/ui-system-proof.sh` are already written and already failing;
  S8 makes the script print `026.1 ok: …` without editing its assertions.

## Non-goals

- **No workspace template.** No W1 table, no W2 entity page, no W3, W4, W5.
  Operations is a single card, not a template instance.
- **No new dependency and no new shadcn component.** EPIC 026 decision 9
  installed the set; a gap raises an `OPEN:` blocker.
- **No new API route and no API call beyond `/healthz`, `/api/project` and
  `/api/project/:id`.** Everything else is 026.2–026.8.
- **No polling.** Decision 9 defers it to 026.2.
- **No `⌘K` command palette.** The header slot exists; the palette needs
  cross-surface targets that do not exist until 026.2.
- **No backend/UI contract generation** (decision 8).
