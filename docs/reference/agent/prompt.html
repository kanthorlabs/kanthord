Resolve the prompt of an execution

Function description

Rebuild the exact system prompt that one agent of an execution served. The API and kanthord agent prompt resolve perform the same read and change no state.

KanthorD stores no copy of a prompt text. The execution setup stores one agent.prompt span for each agent of the execution. The span holds a prompt reference for each part and the engine version, and no text. The read finds that span, resolves each reference by its origin and checks each digest:

origin The read takes the text from A failure answers
database prompts.repository or prompts.agents[<agent_name>] of the binding revision binding_id. A binding revision never changes. changed when the text is absent
repository The file path at commit of the binding binding_id, read from git with the SSH access of the binding. unreachable when the read of the remote fails or exceeds its deadline, invalid for a file that is larger than 32768 bytes, is not UTF-8, cannot be read or holds a control character other than a tab and a newline, changed for an absent file
binary The shipped text of the current binary. changed when the current text has another digest
file The current file of agent.prompt.agent_directory. changed for an absent file or another digest, invalid for a file that is larger than 32768 bytes, is not UTF-8, cannot be read or holds a control character other than a tab and a newline

Each resolved text passes a digest check against the digest of its reference. A text with another digest answers changed with a null text. A failed part is a part state, and the read answers 200. The read takes every instruction file in parallel under one deadline of 20 seconds.

The read takes only the references that the server wrote in a span. It reads no file that the caller names.

Expected response

The API returns HTTP 200 with { parts, final, engine_version }. The CLI writes the same object as one JSON line to stdout and exits 0. The example below is shortened. The edited base.md of a later deploy makes its part changed. 

{
  "parts": [
    {
      "layer": 1,
      "part": "standard",
      "name": "base.md",
      "origin": "binary",
      "path": "/home/kanthord/.local/share/kanthord/agents/base.md",
      "binding_id": null,
      "commit": null,
      "digest": "fc0e6acdff4574d8a819453138969678876fe1ae87c3760b905e540b90d51caa",
      "heading": null,
      "state": "changed",
      "text": null
    }
  ],
  "final": null,
  "engine_version": "28.0.1"
}
Property Type Purpose
parts array The parts of the span in reading order, the framing last. Each part holds the fields of the prompt part of agent get. Each part holds the digest and the commit of its span reference, also when the part is not resolved.
final string or null The system prompt that the execution served. null when a part is not resolved.
engine_version string The value of kanthord.engine.version of the span: the engine version that served the execution.

Read an old shipped text

KanthorD keeps no copy of a layer 1 text. A deploy that edits a shipped text therefore turns every older trace into changed for that part, with final: null. To read the old text of a changed part of origin binary, run one of these commands in a root checkout of the kanthord repository. Run git fetch --tags and git -C engine fetch first, so that the checkout holds the release tag and the engine commit: 

git -C engine show "$(git rev-parse "v<engine_version>:engine"):static/prompt/<name>"
git -C engine show "$(git rev-parse "v<engine_version>:engine"):static/prompt/template/<name>.md"
  • The first command reads a part with the file name <name>, for example base.md.
  • The second command reads a framing part, for example framing-worker.
  • The release tag v<engine_version> of the root repository names the engine commit. A development build has no release tag, so its version names no unique engine commit.
  • For a changed part of origin file, read the old file from the version control of the agent directory.

Compare the system prompts of two executions with diff: 

diff <(kanthord agent prompt resolve --execution E1 --agent re@1 | jq -r .final) <(kanthord agent prompt resolve --execution E2 --agent re@1 | jq -r .final)

Failures

API failures use the shared error envelope.

HTTP status / code Meaning
401 gateway.authentication.unauthorized Missing, invalid, expired or banned token, or a machine token.
400 gateway.request.validation_failed execution_id or agent_name is absent or empty.
404 scheduler.execution.not_found execution_id names no execution.
404 agent.prompt.record_absent The trace of the execution holds no agent.prompt span for the agent. details holds execution_id and agent_name. An execution of an external harness has no such span.

The CLI checks some input before it sends the request:

CLI code Meaning
cli.agent.prompt.resolve.token_required No option, environment variable or client file supplies a token.
cli.agent.prompt.resolve.indeterminate A transport failure, timeout or malformed response. Retry the command.

API shape

Item Value
Method and path GET /api/agent/prompt/resolve
Operation ID agent.prompt.resolve
Access human (human bearer JWT)
Timeout 30 seconds
Mutation No
Request body None; a nonempty body fails with 400 gateway.request.unexpected_body

The static path /api/agent/prompt/resolve takes precedence over /api/agent/:agent_name.

Parameter In Required Purpose
execution_id query Yes The execution.
agent_name query Yes The agent of the execution, for example re@1. 
curl -s 'http://127.0.0.1:31415/api/agent/prompt/resolve?execution_id=<execution-id>&agent_name=re@1' \
  -H 'Authorization: Bearer <human-jwt>'

CLI shape

kanthord agent prompt resolve --execution <execution-id> --agent <agent-name> [--token <jwt>] [--endpoint <url>]
Option Default / resolution Purpose
--execution <execution-id> Required Sets execution_id.
--agent <agent-name> Required Sets agent_name.
--token <jwt> KANTHORD_TOKEN → client-file token; a nonblank resolved token is required Human JWT sent as the bearer credential.
--endpoint <url> KANTHORD_ENDPOINT → client-file endpoint → http://127.0.0.1:31415 Server base URL.

The agent group declares --token and --endpoint. See client configuration.
