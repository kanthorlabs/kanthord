Get an agent declaration

Function description

Read the catalog declaration of one agent, its composed prompt, its permitted tools, its global enablement and the fallback chain of that enablement. The API and kanthord agent get perform the same read and change no state.

The catalog holds the agents swe@1, re@1 and env@1. An agent name outside the catalog fails. The answer contains enablement: null when the agent has no live enablement.

The server composes the prompt at read time from three prompt layers. Layer 1, the KanthorD prompt, holds the files base.md, <agent_name>.md and, for a Workbench agent, workbench.md. Layer 2, the Repository prompt, holds the instruction file that prompts.instruction_file of a repository binding names, then the text of prompts.repository. Layer 3, the Binding prompt, holds the text of prompts.agents[<agent_name>]. The framing is KanthorD protocol and no layer. It closes the system prompt.

A file of the same name in the directory agent.prompt.agent_directory of the server host replaces the shipped text. The default directory is <data>/agents. An empty value selects the shipped texts only. A file <name>.md in the subdirectory prompts of the agent directory replaces the shipped prompt template of that name, for example prompts/framing-worker.md.

An override file or a template file that is not a regular UTF-8 file, exceeds 32768 bytes or holds a control character other than a tab and a newline answers 409 agent.prompt.template_invalid with details.file. No reader falls back to the shipped text. The execution setup, the Workbench session open and the env@1 run refuse in the same way.

The read selects the repository bindings in one of three ways:

  • With no binding query, a Workbench agent answers the Workbench system prompt, and env@1 answers the worker system prompt. No layer 2 or layer 3 part joins.
  • With project_id and binding_id, final is the worker system prompt with layers 2 and 3 of that binding. The read takes the instruction file at the current head of the base branch, as the next attempt takes it.
  • With node_id, final is the worker system prompt with layers 2 and 3 of each repository binding of the node revision that the attempt pins. The read takes the instruction file at the commit that the attempt pins, and at the current base head for an attempt with no pin. Without attempt, the read takes the open attempt, else the latest attempt.

The read takes every instruction file in parallel under one deadline of 20 seconds. A failed read of an instruction file is a part state, and the read answers 200. KanthorD reads only the one file that prompts.instruction_file names. It reads no nested file, no *.local.md file and no file of a home directory.

Property Type Purpose
agent_name string Catalog key of the agent.
configuration_schema object JSON Schema draft 2020-12 of the effective configuration. JSON Schema does not check that the model belongs to the provider or that the model supports the reasoning effort.
overridable_fields string array Fields that a binding entry can override. For swe@1 and re@1 the value is agent_provider, model_identifier, reasoning_effort and fallback_configurations.
prompt.parts array The parts of the system prompt in reading order. Absent with view=final. See the part table below.
prompt.final string or null The composed system prompt: every part in reading order, the framing last. A part with a heading renders as the heading, a blank line and the text. null when a part is not resolved.
tools array Permitted tools. Each item holds name, source (host, builtin or kanthord-mcp) and input_schema.
enablement object or null The live enablement record, or null when no live record exists.
chain array The fallback chain of the enablement: the default configuration, then its fallback_configurations. [] when the enablement is absent, disabled or invalid. See the chain table below.
active_position integer or null The position of the first chain entry whose cooldown is null or ended. null when every chain entry has a live cooldown, and when chain is empty.
cooling object or null { code, available_at } with code agent.configuration.chain_cooling and the earliest available_at of the chain, when every chain entry has a live cooldown. Otherwise null.

Each chain item holds these fields:

Property Type Purpose
position integer Position in the chain. 0 is the head.
level string enablement or binding. This view holds only enablement.
agent_provider string Name of the agent provider.
provider string Provider kind of the agent provider.
credential string Credential name of the agent provider.
model_identifier string Model of the chain entry.
reasoning_effort string Reasoning effort of the chain entry.
cooldown object or null null, or { strikes, available_at } of the cooldown of the server copy of the credential. Every model of a credential shows the same value.

A hold that expired still shows in cooldown with its strikes and a past available_at until a success or a clear. Selection treats an expired hold as free.

prompt.parts holds the parts in reading order:

  1. standard: base.md, for every agent.
  2. role: <agent_name>.md.
  3. workbench: workbench.md, only in the Workbench system prompt.
  4. For each repository binding, in the order of the repository bindings of the node revision: instruction_file, then repository, then binding. An absent instruction file, an absent text and a blank text add no part.
  5. framing: the rendered framing template. It closes the system prompt.

Each part holds these fields:

Property Type Purpose
layer integer or null The prompt layer: 1 for standard, role and workbench, 2 for instruction_file and repository, 3 for binding. null for framing.
part string standard, role, workbench, instruction_file, repository, binding or framing.
name string The file name of a layer 1 part, for example base.md. The template name of framing, for example framing-worker. The repository binding name of a layer 2 or layer 3 part.
origin string binary for a shipped text, file for an override file, database for repository and binding, repository for instruction_file.
path string or null The override path that the server looked up, also for binary. The repository path for instruction_file. null for repository and binding, and when the agent directory is empty.
binding_id string or null The binding revision of a layer 2 or layer 3 part. null otherwise.
commit string or null The commit of an instruction_file part, 40 or 64 lower-case hex. null for every other part, and for an instruction file whose base head the server cannot read.
digest string or null The SHA-256 hex digest of the exact UTF-8 text, with no heading. null for a part that the server cannot read.
heading string or null The line before the text: Repository prompt of repository <name>, file <path>: for instruction_file, Repository prompt of repository <name>, set in KanthorD: for repository, Binding prompt of repository <name>: for binding. null for the other parts.
state string resolved. An instruction_file part is unreachable when the read of the remote fails or exceeds its deadline, and invalid when the file is larger than 32768 bytes, is not UTF-8, cannot be read or holds a control character other than a tab and a newline. A carriage return counts, so a file with CRLF line ends is invalid. The prompt resolve also answers changed.
text string or null The text of a resolved part. null otherwise.

The first seven fields after layer form the prompt reference of the part.

The precedence of the system prompt is the framing, then the Binding prompt, then the stored Repository prompt, then the instruction file, then workbench.md, then the role, then the standard. A later text governs an earlier one, and a later message governs an earlier one.

Selection

  • The claim selects the first chain entry whose credential is not cooling. It records each selection as the agent name, the enablement revision and the chain position.
  • The execution record and the release rebuild the pinned selection from these pins.
  • The pinned selection fixes the agent provider, the provider, the credential, the model and the reasoning effort. The authorization of custody and the execution setup of the Worker Service read them from it.
  • An enablement edit during a live execution changes none of them. A disabled or removed current enablement still stops both with 400 agent.enablement.unavailable.

Failures

API failures use the shared error envelope.

HTTP status / code Meaning
401 gateway.authentication.unauthorized Missing, invalid, expired or banned token, or a machine token.
400 gateway.request.validation_failed view is not final, only one of project_id and binding_id is present, attempt comes without node_id, or node_id comes with project_id or binding_id.
404 agent.catalog.not_found The agent name is not in the catalog.
404 project.binding.not_found binding_id names no repository binding of the project project_id.
404 mission.node.not_found node_id names no mission node.
404 mission.record.not_found The node holds no attempt, or no attempt attempt.
409 agent.prompt.template_invalid An override file or a template file of the agent directory is invalid. details holds file, path and reason.

The CLI checks some input before it sends the request:

CLI code Meaning
cli.agent.get.invalid_view The --view value is not final.
cli.agent.get.project_binding_pair_required Only one of --project and --binding-id is present.
cli.agent.get.token_required No option, environment variable or client file supplies a token.
cli.agent.get.indeterminate A transport failure, timeout or malformed response. Retry the command.

A declared failure makes the CLI exit 1 and print <code>: request failed and the row status: <status> to stderr.

API shape

Item Value
Method and path GET /api/agent/:agent_name
Operation ID agent.get
Access human (human bearer JWT)
Timeout 30 seconds
Mutation No
Request body None; a nonempty body fails with 400 gateway.request.unexpected_body
Parameter In Required Purpose
agent_name path Yes Catalog key, for example swe@1.
view query No The only value is final. The answer then omits prompt.parts.
project_id query Only together with binding_id Project of the repository binding.
binding_id query Only together with project_id Repository binding whose layers 2 and 3 join final.
node_id query No; excludes project_id and binding_id Mission node whose agent stack the read answers.
attempt query Only together with node_id Positive integer. The attempt whose prompt pin the read takes. Without it, the open attempt, else the latest attempt.
Header Required Purpose
Authorization Yes Bearer <human-jwt>. 
curl -s 'http://127.0.0.1:31415/api/agent/swe@1?view=final' \
  -H 'Authorization: Bearer <human-jwt>'

CLI shape

kanthord agent get <agent-name> [--view final] [--project <project-id> --binding-id <binding-id> | --node <node-id> [--attempt <k>]] [--token <jwt>] [--endpoint <url>]
kanthord agent get swe@1 --view final
kanthord agent get swe@1 --project <project-id> --binding-id <binding-id>
kanthord agent get re@1 --node <node-id> --attempt 2 --view final
Argument Required Purpose
<agent-name> Yes Catalog key; maps to agent_name.
Option Default / resolution Purpose
--view <view> None; the only value is final Answer prompt.final without prompt.parts.
--project <project-id> None; requires --binding-id Sets project_id.
--binding-id <binding-id> None; requires --project Sets binding_id.
--node <node-id> None; excludes --project and --binding-id Sets node_id.
--attempt <k> None; requires --node Sets attempt. The server checks the value.
--token <jwt> KANTHORD_TOKEN → client-file token; a nonblank resolved token is required Human JWT sent as the bearer credential.
--endpoint <url> KANTHORD_ENDPOINT → client-file endpoint → http://127.0.0.1:31415 Server base URL.

The agent group declares --token and --endpoint. Put them before or after the leaf command. Each option except --endpoint accepts one occurrence only; a repeat fails with cli.option.duplicate. See client configuration. The HTTP client has a 31-second deadline for this 30-second operation.
