Manage worker machines

Function description

A worker machine is one computer that runs worker instances at the worker placement. It is a credential holder with its own X25519 key pair. The instances of one machine share one copy of each credential that the machine holds; see instance and machine copies. A machine holds no token, no connection, no binding and no execution. A worker machine is no host: the host of a worker stays kanthord or an external harness.

Each instance at the worker placement names one live machine at its create. The machine of an instance never changes. The server and the container placements name no machine. The server stores only the public key of a machine. The private key stays in the machine configuration on the machine.

Each machine has revisions. Each revision has its own worker_machine_<ulid> identity, key and fingerprint. The live revision of a name is its newest revision with ended_at null. A name with no live revision is archived.

  • worker machine create stores revision 1 of a new name. The name follows the instance name form: 1 to 63 characters, ^[a-z][a-z0-9-]*$. The names server, token, connect, heartbeat and work are reserved. Machines and instances share one name space. A live or an archived machine or instance name stays taken.
  • worker machine list pages the newest revision of each name in ascending name order, with the count of its live instances.
  • worker machine get reads the live or the latest revision of one name, with its instances and its credential copies.
  • worker machine rotate is the Reset key of the machine. It ends the live revision and stores the next revision with a new key.
  • worker machine archive ends the live revision for good. It refuses while a live instance names the machine. In one transaction, it archives every credential copy that the machine holds.

No two revisions of any machine or any instance share one fingerprint. Create and rotate take an optional public_key:

  • With public_key, the server stores that key. The CLI generates the key pair on the computer that runs it and sends only public_key.
  • Without public_key, the server generates the key pair and stores only the public key. The answer adds machine_configuration once, with the header Cache-Control: no-store. The server keeps no copy of the private key.

A Reset key of the machine gives a new machine configuration. Each machine copy then has sealed_current false, and the handover refuses it with 403 custody.handover.holder_refused and the reason held_elsewhere. The instances that use such a copy show holder_mismatch true. To recover:

  1. Replace the machine file with kanthord worker machine join --force, or replace the env value.
  2. Sign in again on the machine for each OAuth copy.
  3. Rotate each API key copy with a new secret, and rotate the key at its provider.

An instance that reads the machine file needs no restart after a Reset key of the machine. An instance that reads KANTHORD_MACHINE_CONFIG takes the new value only in a new container. An instance configuration sits on the machine, so a leaked instance configuration also exposes the machine key. Then reset the key of the instance and of the machine.

Machine configuration

  • The machine configuration holds name and private_key. Its value is the unpadded base64url form of its canonical JSON, with no prefix.
  • The machine file $XDG_CONFIG_HOME/kanthord/machines/<name>.yaml holds the same two keys, with mode 0600, in a directory with mode 0700. Without XDG_CONFIG_HOME, the directory is ~/.config/kanthord/machines/.
  • On a computer without a writable configuration, the env value KANTHORD_MACHINE_CONFIG holds the machine configuration. A container host kind sets this value.

kanthord serve worker reads the machine configuration of the machine of each heartbeat answer:

  • The instance claims no work before the first heartbeat answer. An answer with machine null opens the claim.
  • A machine configuration of that name opens the claim. An absent configuration stops the claim and logs worker.machine.config_absent with the machine name once. A later heartbeat that reads the configuration opens the claim again.
  • A worker.machine.config_conflict or worker.machine.config_invalid read at a heartbeat closes the gate and logs its code with the machine name once, as config_absent does.
  • The instance reads the machine key at each use, by the holder of the copy. An instance that reads the machine file needs no restart after a Reset key of the machine. An instance that reads KANTHORD_MACHINE_CONFIG takes the new value only in a new container.
  • The instance checks the name with the instance name form before it builds the file path. join, create --output and rotate --output do the same check, and answer worker.machine.config_invalid.
  • Without --force, join, create --output and rotate --output refuse an existing machine file with the local code cli.worker.machine.config_exists.
  • The agent processes of the instance do not receive KANTHORD_MACHINE_CONFIG.
Code Condition
worker.machine.config_absent No env value and no machine file for the name. The diagnostic names the variable and the file path.
worker.machine.config_conflict The env value and the machine file both hold a value for one name.
worker.machine.config_invalid The name breaks the instance name form, the value fails the schema, the file name differs from its file name, or the env value names another machine.
cli.worker.machine.config_exists join, create --output or rotate --output meets an existing machine file without --force.

Expected response

Machine record

create, rotate and archive answer HTTP 200 with a machine record. list and get add fields to the same record. 

{
  "id": "worker_machine_01M34JC4BJ66JHP41M4MYY6PSM",
  "name": "build-box",
  "revision": 1,
  "public_key": "<43-base64url-characters>",
  "fingerprint": "SHA256:<43-base64-characters>",
  "created_at": 1791467996322,
  "ended_at": null
}
Property Type Purpose
id string Identity of the revision, worker_machine_<ulid>. Each revision has its own identity.
name string Machine name. It never changes.
revision positive integer Revision number of the name, from 1. Each Reset key adds 1.
public_key string Base64url form of the 32-byte X25519 public key of the revision.
fingerprint string SHA256:<unpadded base64 of the SHA-256 of the key>. No two revisions of any machine or any instance share one.
created_at integer Creation time of the revision in Unix milliseconds.
ended_at integer or null End time of the revision in Unix milliseconds. null while the revision is live.

The archive answer is the archived revision, with ended_at set. The rotate answer is the new revision.

worker machine create and worker machine rotate

Without public_key in the request, the API answer adds one field and the header Cache-Control: no-store:

Property Type Purpose
machine_configuration string The machine configuration with the generated private key. The server answers it only once.

The CLI generates the key pair on the computer that runs it and sends only public_key. It writes one JSON line to stdout and exits 0:

Output Purpose
Machine record The answer of the server.
machine_configuration Without --output: the machine configuration. Give it to kanthord worker machine join or to KANTHORD_MACHINE_CONFIG.
created With --output: the path of the machine file that the CLI wrote. The line then holds no private key.

Failures

API failures use the shared error envelope. The gateway failures of worker instances also apply: authentication, request validation, idempotency, the body limit, the media type and the timeout. Every operation requires a human token.

HTTP status / code Commands Meaning
400 worker.machine.name_invalid create The name breaks the instance name form or is reserved. The CLI also checks it before the request.
400 worker.machine.key_invalid create, rotate public_key is no base64url 32-byte X25519 key.
404 worker.machine.not_found get, rotate, archive The machine name or the machine revision is unknown, or the revision ended.
409 worker.machine.name_conflict create A live or an archived machine or instance holds the name.
409 worker.machine.key_conflict create, rotate A machine or an instance revision holds the same key.
409 worker.machine.revision_conflict rotate, archive expected_revision is not the live revision. details.revision names the live revision.
409 worker.machine.archived rotate, archive The machine is archived.
409 worker.machine.in_use archive A live instance names the machine. details.instances lists the instance names.

A declared failure makes the CLI exit 1 and print <code>: request failed and the row status to stderr. A repeated key for create or rotate answers 409 gateway.idempotency.conflict, because the server never replays an answer that holds a secret.

Parameter In Operations Default Rule
machine_name path get, rotate, archive None Machine name. An unknown name answers not found.

Operation Request body
create { "name", "public_key"? }.

Every operation has a timeout of 30 seconds. create, rotate and archive take the header Idempotency-Key. 

curl -i -X POST http://127.0.0.1:31415/api/worker/machine \
  -H 'Authorization: Bearer <human-jwt>' \
  -H 'Idempotency-Key: idempotency_key_01M34JC4BJ66JHP41M4MYY6PST' \
  -H 'Content-Type: application/json' \
  -d '{"name":"build-box"}'

curl -i http://127.0.0.1:31415/api/worker/machine/build-box \
  -H 'Authorization: Bearer <human-jwt>'

curl -i -X POST http://127.0.0.1:31415/api/worker/machine/build-box/archive \
  -H 'Authorization: Bearer <human-jwt>' \
  -H 'Idempotency-Key: idempotency_key_01M34JC4BJ66JHP41M4MYY6PSD' \
  -H 'Content-Type: application/json' \
  -d '{"expected_revision":1}'

Option Commands Purpose
--expected-revision <revision> rotate, archive Required. Live revision of the machine.
--output create, rotate Writes the machine file machines/<name>.yaml on this computer in place of the configuration on stdout.
--force create, rotate, join Overwrites an existing machine file.
--limit <count> list Page size; a positive integer up to 1000.
--cursor <opaque> list next_cursor of the previous page.
--idempotency-key <key> create, rotate, archive Sets the Idempotency-Key header.

Run create and rotate with --output on the machine. Without --output, stdout must be a terminal, because the line holds the private key. The CLI refuses a malformed or reserved name with worker.machine.name_invalid before it sends a request.

worker machine join

kanthord worker machine join reads one machine configuration from stdin and writes the machine file machines/<name>.yaml, with mode 0600. It sends no request. Run it once on each machine. A container host kind sets KANTHORD_MACHINE_CONFIG instead. A value that fails the schema answers worker.machine.config_invalid. Without --force, an existing file refuses.

See shared options for --token and --endpoint.
