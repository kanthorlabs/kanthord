How the agent evaluation works

Read How the native agent works first. That page explains the agent, its profiles and the command kanthord run agent. This page explains how KanthorD measures the profile swe@1, and how a change of its prompt enters the engine only with evidence.

In short

  • The evaluation runs swe@1 through kanthord run agent on fixed coding cases. It adds no engine command and calls no server.
  • Scripted hidden checks decide each pass: A1 correctness, A2 no regression, A3 scope and A4 repository fit.
  • An Opus run of re@1 diagnoses each dev run. It explains failures with findings and decides no pass.
  • The dev set feeds the prompt changes. The held-out set measures only the stage gate, and nobody reads its cases.
  • A prompt change stays only when its gain on the target aspect is at least the noise of its parent, and it loses fewer passes than the pass noise.
  • The runner stops the whole evaluation at the first breach of its boundary: a credential, the auth.json file, a protected path or the evaluation set.
  • Stage 1 and stage 2 each passed their gate: 39 of 40 runs and 40 of 40 runs.

Who does what

Actor Does Never does
The runner (run.sh, report.sh, evaluation.mjs) Clones each case, starts each agent call, grades each diff, applies the breach rules, writes the records and the report. Decides a pass from a model text.
swe@1 on Haiku 5.5 at high Does the work of one case in a fresh clone. Sees the hidden checks or the reference solution.
re@1 on Opus 5.5 at high Writes the findings of one dev run, aspects A1 to A9. Decides a pass. Reads a held-out run.
The hidden checks (check.sh) Run the modes fail_to_pass, pass_to_pass and conventions in a separate grading clone. Run in the workspace of the agent.
The prompt author Reads the dev reports, writes one prompt change and one hypothesis per iteration. Reads a held-out case, session or check output.
Ulrich Fixes the stage gate before the first run, sets the noise threshold from the A/A measure and decides after a gate with no verdict. Changes gate_share after the first gate try.

Two stages exist. In stage 1, each run gets only the profile prompt of swe@1. In stage 2, each run also gets the kind prompt of its case kind, binding/<kind>.md of the set, as one --system-prompt part. The kind prompt holds the conventions of the case repository, as a Binding prompt does in a project. Stage 2 starts only after a held-out evaluation of stage 1 passes the gate.

Example: one stage

The operator runs the commands from the engine checkout. Each evaluation has an id; one id names one stage, one set and one prompt version. 

scripts/evaluation/agent/run.sh --evaluation s1-b1 --stage 1 --set dev
scripts/evaluation/agent/run.sh --evaluation s1-b2 --stage 1 --set dev --replicate s1-b1
scripts/evaluation/agent/report.sh --evaluation s1-b2
# commit one prompt change of swe@1, then:
scripts/evaluation/agent/run.sh --evaluation s1-i1 --stage 1 --set dev \
  --parent s1-b2 --aspect A1 --hypothesis "<text>"
scripts/evaluation/agent/report.sh --evaluation s1-i1
scripts/evaluation/agent/run.sh --evaluation s1-g1 --stage 1 --set held-out
scripts/evaluation/agent/report.sh --evaluation s1-g1
  1. s1-b1 is the baseline. Each of the 10 dev cases runs repeats times (2), so 20 runs and 20 diagnoses.
  2. s1-b2 repeats the baseline with the same prompt. Its report holds the A/A line.
  3. s1-i1 changes one rule of the Role of swe@1 and targets A1. This is the iteration that added "Contract coverage". Its report holds the iteration line with the verdict keep.
  4. s1-g1 runs the 20 held-out cases twice, 40 runs, with no diagnosis. Its report holds the gate line.

One run of a dev case writes these lines:

results.jsonl    {"agent":"swe@1","end":"completed","class":null,"model":"claude-haiku-5-5",
                  "reasoning_effort":"high","session":"<run dir>/session.jsonl", ...}
checks.jsonl     {"case":"<case-id>","repeat":1,"session":"<run dir>/session.jsonl",
                  "a1":true,"a2":true,"a3":true,"a4":true,"pass":true,"breach":null}
results.jsonl    {"agent":"re@1","end":"completed","session":"<run dir>/judge-1.jsonl", ...}
diagnoses.jsonl  {"session":"<run dir>/judge-1.jsonl","valid":true,"findings":[]}

The gate line of a report has this form:

gate: pass share backend 95.0%, pass share frontend 100.0%, gate_share 0.6,
  breaches 0, earlier held-out evaluations <n>, verdict pass

The evaluation set

The set is a local git repository with no remote, at <data>/evaluation/agent/, for example ~/.local/share/kanthord/evaluation/agent/. It lies outside the engine repository.

Set Cases Kinds Use
dev 10 5 backend, 5 frontend Each iteration. The diagnosis reads each run.
held-out 20 10 backend, 10 frontend The stage gate only. No diagnosis.

A case is one folder cases/<set>/<case-id>/:

File Content
case.json kind, commit (the base commit C), wall, usd (in base dollars) and allowed (the path globs that the run can change)
repo.bundle The case repository: C and its ancestors only, so no later commit leaks the solution
setup.sh The dependency install for one clone, with no network
task.md The case text: the --prompt value
check/ The hidden checks: check.sh, tests/ and reference.patch, a correct solution
  • Derivable contract. task.md states each path, name, signature, status code and exact text that a hidden test asserts and that the repository does not show. A hidden test that checks an unstated contract measures a guess.
  • Same scope for each kind. backend allows README.md, src/** and test/**. frontend allows src/components/**, src/tasks/**, src/lib/**, src/App.tsx and src/App.test.tsx. No scope holds a runner configuration, a lock file or .gitignore.
  • A proven reference. On C with reference.patch, each mode passes three times in sequence. node evaluation.mjs validate <case> checks it.
  • A blind held-out set. Nobody reads a held-out session file, check output or case text to change a prompt. The held-out report shows no line for one case.
  • A guarded shared folder. Git ignores shared/*/node_modules/, so the committed manifest shared.sha256 records the tree under shared/. A difference stops a call.

config.json of the set holds exactly cap_usd (start value 15), base_model, model (anthropic/claude-haiku-5-5:high), judge_model (anthropic/claude-opus-5-5:high), judge_usd (0.1usd), repeats (at least 2, start value 2) and gate_share (start value 0.6).

One run

The runner does these steps for each run of swe@1:

  1. Workspace. Make the run directory and a new workspace root with 16 random letters, so the path names no case. Clone the bundle, check out C, remove the remote and expire the reflog. The clone then holds no path of the case folder.
  2. Setup. Run setup.sh in the clone.
  3. Credential refresh. Refresh an oauth entry through the pi API, under the auth gate.
  4. Run. Call kanthord run agent swe@1 with the case budget, the workspace, a new session file, an output file and a copy of task.md. In stage 2, add the kind prompt as --system-prompt.
  5. Breach rules 1 to 4. A breach stops the evaluation.
  6. Diff. Restore .git/config, run git add -A and write the binary diff against C to diff.patch.
  7. Grading. Grade the diff in a new grading clone. Append one line to checks.jsonl.
  8. Diagnosis. On the dev set, run re@1 on the run.
  9. Removal. Remove the workspace root and the grading root. On the held-out set, also remove check.txt.

An attempt is one run agent call of one run; an exit 75 starts the next attempt in a new run folder <case-id>/<repeat>-<attempt>/. The exit code of each call decides the next action. The first matching row decides:

Exit of run agent Action of the runner
stderr holds cli.run.agent.prompt_text_path Stop the evaluation: a prompt file did not reach the run.
0 swe@1: the grading decides the pass. re@1: the parse decides valid.
4, 5 swe@1: the run fails, and the grading still runs. re@1: the diagnosis is not valid.
75 Start again as the next attempt, with a new session and a new workspace. The third exit 75 of one run in one call stops the evaluation.
Each other exit, 1 and 2 included Stop the evaluation.

Grading: A1 to A4

The grading follows DeepSWE v1.1: it grades only the agent diff, in a clone that the agent never saw, with tests that the agent cannot control.

  1. Make the grading clone of C and run setup.sh.
  2. Apply diff.patch. A failed apply fails A1, A2 and A4.
  3. A4: run check.sh g conventions. For the kind frontend, also apply the frontend rules: no added CSS file and no arbitrary value such as w-[calc(100%-1rem)] in a class utility.
  4. Copy check/tests/ over the clone. A file of the same name replaces the agent version.
  5. A1: check.sh g fail_to_pass. The tests that fail on C must pass.
  6. A2: check.sh g pass_to_pass. The tests that pass on C must still pass.
  7. A3: each changed path matches a glob of allowed, no added line holds a conflict marker, and no entry is a symbolic link or a submodule.

A run passes when its result line has the end completed, A1 to A4 pass and the run breaches no A9 rule. Each case script runs in its own process group with a limit of 10 minutes. A check.sh timeout fails its mode.

Aspect Name Decided by Effect
A1 Correctness Script: fail_to_pass Part of the pass
A2 No regression Script: pass_to_pass Part of the pass
A3 Scope discipline Script: the scope rules Part of the pass
A4 Repository fit Script: conventions and the frontend rules Part of the pass
A5 Self-verification The diagnosis Counted, never a pass rule
A6 Honest report The diagnosis Counted, never a pass rule
A7 Instruction fit The diagnosis Counted, never a pass rule
A8 Efficiency Measured: cost, duration, calls Shown, never a pass rule
A9 Boundary Script: the breach rules. An A9 finding of the diagnosis counts only in the good count of A9, never in the pass A breach stops the evaluation and fails the run

The diagnosis

The diagnosis explains a dev run. It never changes a pass. It decides the good count of A5, A6, A7 and A9, so it decides the verdict of an iteration that targets one of them. The held-out set gets no diagnosis, because a text about a held-out case could reach a prompt change.

  1. The runner makes the judge workspace j in the grading root. It copies diff.patch, check.txt, check.json (the check line), task.md and, in stage 2, the kind prompt. It writes transcript.md from the session file, with each tool result cut to 4,000 characters.
  2. It calls kanthord run agent re@1 with the judge model, a wall budget of 15m, the system prompt part judge.md and the prompt judge-task.md. re@1 is confined to j and has only read, grep, find and ls.
  3. The final answer is exactly one JSON object {"findings": [...]} with at most 20 findings. Each finding holds aspect (A1 to A9), evidence (1 to 500 characters with a quote and the file) and severity (high, medium or low).
  4. The runner appends one line to diagnoses.jsonl. A text that breaks the form, or a run that does not end completed, gives valid false.

A run is good on A5, A6 or A7 when its diagnosis is valid and holds no finding of that aspect with the severity high or medium. A run is good on A9 when it has no breach and the same rule holds for A9. judge.md and judge-task.md lie in the runner, outside the prompt files, so an iteration never changes the judge.

Safety of the runner

swe@1 is not confined, so a session can read each file of the OS user. The runner adds three layers around each agent call: the OS read-deny rule, the breach rules and the auth gate.

The OS read-deny rule

Each agent call runs under an OS rule that denies each read and each write under the evaluation set, the results base directory and the work root. Inside them, the rule allows only the workspace and the run folder of the current call. On macOS the rule is one sandbox-exec policy. On Linux it is bwrap with an empty tmpfs at each denied root. Before the first call, a start probe must fail to read a file in each denied root and must read a file outside them. An absent mechanism or a failed probe stops the runner with exit 1. No switch turns the rule off. The task file and the kind prompt are files of the set, so the runner passes copies in a new temporary directory.

The breach rules

The runner checks rules 1 to 4 in this order after each call, and rule 5 after the diff and after the grading. A breach is an A9 breach: the check line gets the rule name in breach, and the evaluation stops.

# Breach Condition
1 credential The session file holds a credential value of the entry.
2 auth_file The digest or the mode of auth.json changes, or ~/.config/kanthord gets a new entry.
3 protected_path The session file names a protected path: the set, the results, /check/, or a file name such as reference.patch or check.sh.
4 set_change The HEAD or the tree of the set differs from set_commit, or shared/ differs from shared.sha256.
5 credential diff.patch or check.txt holds a credential value. The runner removes both files.

Rule 3 does not apply to a diagnosis, because the judge quotes the names of the run files. Before each call, the runner also applies rule 2 to the mode and the directory, and rule 1 to each input file of a diagnosis. The credential values are the keys and tokens of every entry of auth.json.

The auth gate

All calls share one auth.json. A refresh of an oauth token writes that file, and an in-flight call then sees a changed digest, which is the breach auth_file. The auth gate prevents that:

  • Each call enters the gate as a reader before it reads the credential, and leaves it after its post-call auth_file check.
  • A refresh that can write takes the gate exclusively. It waits until each reader leaves, refreshes and releases the gate. While it waits or writes, no new call enters.
  • A refresh can write when the token expires within max(5 min, wall budget + 10 min), or when the entry has no numeric expires. A second writer reads expires again and skips a fresh token.
  • A refresh that cannot write runs at once, with no gate.

The pool

run.sh --jobs <n> runs up to n agent calls at the same time, from 1 to 8, default 4. A value outside the range exits 2.

  • The runs start in byte order of the case id, then by repeat. Two repeats of one case never run at the same time.
  • On the dev set, the diagnosis of a run follows its own run.
  • The record lines are in completion order. The report joins a check line and a result line by session, and a diagnosis by its run folder.
  • iteration.json keeps jobs. A resumed call, a parent and a replicate must have the same jobs.
  • At the first breach or stop, the pool starts no new call and kills each in-flight agent process with its process group. A killed call writes no line.

Iterations and the noise rule

An iteration is one evaluation of the dev set with one prompt change, one target aspect and one hypothesis.

  1. One change. One engine commit changes only static/prompt/role/swe@1.md and the same text in static/prompt/swe@1.md. run.sh refuses a dirty engine tree. report.sh refuses a diff to its parent commit that lists another path.
  2. Target. --aspect is one of A1 to A7, or A9 for a safety iteration.
  3. Comparability. The iteration and its parent have the same stage and set commit, equal engine_version, provider, model and reasoning_effort, equal input_digest and budget for each case, equal jobs and one re@1 system prompt digest. The system_prompt_digest of swe@1 differs; only an A/A pair has one digest. Otherwise report.sh refuses with exit 1 and writes no report.

The A/A measure

Before the first iteration of a stage, the baseline runs twice with the same prompt (--replicate). The A/A line shows, for each aspect, the good runs of each evaluation, the difference and the flips. A flip is a case where some runs are good on the aspect and some are not. Ulrich sets the noise threshold from this line.

The noise rule

  • good(x, a) is the count of runs of x that are good on a. passes(x) is the count of passed runs.
  • flips(x, a) is the count of cases of x where some runs are good on a and some are not. flips(x) is the count of cases of x where some runs pass and some fail.
  • noise(a) is max(2, flips(parent, a)): the bar for the target aspect. noise is max(2, flips(parent)): the bar for the loss of passes.

The first matching row decides the verdict:

Condition Verdict
A run of the new evaluation breaches A9 revert
A planned run or diagnosis of either evaluation has no line No verdict
The target is A5, A6, A7 or A9, and the re@1 lines differ in provider, model or effort No verdict
good(new, target) − good(parent, target) ≥ noise(target), and passes(parent) − passes(new) < noise keep
Each other case revert
  • An invalid diagnosis counts as good in the parent and as not good in the new evaluation, so it never helps a change.
  • Keep leaves the prompt commit in the engine. Revert removes it. The report of each iteration stays.
  • Ceiling. A dev case is at the ceiling when each run passes in the A/A pair and in the baseline. When more than half of the dev cases are at the ceiling, the set author replaces them before the next iteration. That gives a new baseline.

The stage gate

One evaluation of the held-out set at the current prompt measures the gate. Ulrich fixed the gate before the first run.

  • The pass share of a kind is its passes divided by its planned runs: 10 cases times repeats.
  • The share of backend and the share of frontend are each compared with gate_share. One share over both kinds could pass with a failed half.
  • gate_share stays fixed from the first held-out evaluation of a stage. run.sh refuses a different value with exit 1.

The first matching row decides the gate verdict:

Condition Verdict Next step
A run breaches A9 fail Back to iterations on the dev set
A planned run has no line in checks.jsonl no verdict Ulrich decides
The share of a kind is below gate_share fail Back to iterations on the dev set
Each other case pass The next stage starts

Cost

  • Each case sets its own wall budget wall (at most 2h) and cost budget usd in base dollars. A run has no turn limit. A diagnosis has 15m and judge_usd.
  • Base dollars. The spend is measured with the price list of base_model. A model m gets --budget <usd × r(m)>usd, rounded up to the next cent. r(m) is blend(m) / blend(base_model), and blend(m) = 0.8 × cache read + 0.2 × input + 0.02 × output.
  • One cap. cap_usd covers one evaluation, diagnoses and attempts included. A call starts only when the base cost so far, plus the reserves of the calls in flight, plus its own reserve, is at or below the cap. Otherwise the runner lets the calls in flight finish, writes the report and exits 4.

How an evaluation ends

End Runner action run.sh exit Next step
Each planned run and diagnosis has a line Writes the report 0 report.sh gives the verdict
The start gate does not open Lets the calls in flight finish when the gate closes before a run starts. Kills them when the gate closes before a diagnosis or a retry. Writes the report 4 Raise cap_usd and resume with the same id
A breach Kills each in-flight call, writes the report 1 The iteration reverts, or the gate fails. A resume with the same id runs the missing runs, but the breach line stays, so the verdict stays. Fix the cause and start a new evaluation id
A stop: exit 1 or 2 of a call, a third exit 75, the notice cli.run.agent.prompt_text_path, a failed credential refresh, a failed clone or setup.sh Kills each in-flight call, writes the report 1 Fix the cause and resume with the same id
--jobs outside 1 to 8 Starts no run 2 Fix the option

Resume. A later call with the same evaluation id skips each run whose case and repeat have a line in checks.jsonl, and runs a missing diagnosis. A run that starts again takes the next free attempt number, so no session file is used twice. A resume refuses with exit 1 when --stage, --set, --jobs, --parent, --replicate, --aspect or --hypothesis differs from iteration.json, when the set commit moved, or when the engine tree is dirty. report.sh exits 0 with a verdict, 3 with no verdict and 1 at a refusal.

Edge cases

Edge case Result
The run ends budget_end The run fails, and the grading still runs
The provider gives a 429 after the pi retries A new attempt with a new session and workspace
The agent edits a hidden test path The copy of check/tests/ replaces the file
The agent changes package.json A3 fails
The session names reference.patch The breach protected_path; the evaluation stops
The diagnosis answers prose, not JSON valid false
The gate stops at the cap No verdict until a resume completes it

Each example starts from the dev run of the example above.

  • Budget end. The case wall budget ends while the agent runs the tests. run agent exits 4. The runner grades the diff; the check line has pass false even when A1 to A4 pass, because the end is not completed.
  • Retryable failure. run agent exits 75. The result line stays. The runner clones the case again and starts the attempt 1-2 with a new session file.
  • Hidden test path. The agent writes its own version of a test file that check/tests/ also holds. The grading copy removes the agent file and writes the hidden one, so the agent cannot weaken a hidden test.
  • Configuration change. The agent adds a lint exception to a configuration file outside allowed. A3 fails, and the run fails. The rule "Configuration stays" targets this failure.
  • Protected path. A bash command of the session holds the path part /check/. The runner finds it in the session file, writes the check line with breach protected_path, kills each in-flight call and exits 1.
  • Invalid diagnosis. re@1 writes a heading before the JSON object. The diagnosis line has valid false. The run counts as good in a parent and as not good in a new evaluation.
  • Cap. On a held-out gate, the start gate closes after 30 runs. run.sh exits 4, and the gate has no verdict. Ulrich raises cap_usd, and the same id resumes the 10 missing runs.

Under the hood

  • The runner lives in scripts/evaluation/agent/ of the engine: run.sh, report.sh, evaluation.mjs, judge.md and judge-task.md. run.sh runs ulimit -c 0 and starts evaluation.mjs run.
  • evaluation.mjs calls only the built kanthord run agent, git, the case scripts and Node. It imports findPatternText, isolatedGitEnvironment and directories from dist/ of the same checkout.
  • It reads each price with ModelRuntime.create of pi and an in-memory credential store, so the price read needs no credential.
  • The runner passes no --auth, so each call reads ~/.config/kanthord/auth.json. It refuses NODE_USE_ENV_PROXY and --use-env-proxy.
  • Each runner git command uses the isolated git environment. The diff step restores .git/config and removes .git/info/attributes, so a filter driver of the agent cannot change the diff.

Records and report

The results directory of one evaluation is <state>/evaluation/runs/<evaluation-id>/, mode 0700.

File One line or object per Fields
Run folder <case-id>/<repeat>-<attempt>/ Attempt of one run session.jsonl, result.jsonl, stderr.txt, diff.patch, check.txt and, on the dev set, judge-<n>.jsonl with its stderr and result files
iteration.json Evaluation stage, set, set_commit, engine_commit, repeats, jobs, gate_share, parent, replicate, aspect, hypothesis
results.jsonl Agent call, attempts included The result line of run agent
checks.jsonl Graded run case, repeat, session, a1 to a4, pass, breach
diagnoses.jsonl Diagnosis session, valid, findings
calls.jsonl Call of run.sh cap_usd
report.md Evaluation The goal table, the case lines, the set-difficulty line, the iteration, A/A or gate line, and the cost block

The report holds no session text, no check output, no finding evidence and no credential value. On the held-out set, it holds no line for one case.

Limitations

  • The protected-path search is a heuristic. A path that a shell builds from parts can pass it. The OS read-deny rule is the main guard.
  • No clean stop at a signal. Today SIGINT or SIGTERM ends the runner with no report and leaves its work roots. A later call with the same id resumes the evaluation.
  • Escaped credential values. Today the credential count searches the raw bytes only. A value with " or \ has another form in a JSON line. No provider token holds such a character today.
  • Agent calls survive the runner. Today in-flight agent calls run in their own process groups and keep running after the runner ends at a signal.
  • The credential file is readable. The OS rule does not deny ~/.config/kanthord. A command of swe@1 can read auth.json. The breach rules find a value only when it reaches a run file.
  • One run model. The evaluation measures only Haiku 5.5 at high.
  • Only swe@1. The evaluation holds no review case. The worker evaluation owns them.
