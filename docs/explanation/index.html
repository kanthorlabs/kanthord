Explanations

These pages answer “How does this work, and why?” They explain mechanisms and design choices rather than prescribing tasks or defining interfaces.

  • Service architecture: a colored Mermaid diagram of all seven services, their components, ownership, and shared runtime.
  • How healthchecks work: interpreting component reports, partial failures, freshness, cancellation, and the limits of diagnostics.
  • How a worker works: start here. The worker concept, the life of an implement node, one execution from pull to release, how reviewer@1 judges, the limits and the rules that hold in every execution.
  • How the coder@1 worker works: the 12 steps of an execution, gate G after every agent turn, the done records, the verdict unit, the release gate, every way that an execution ends, the edge cases with examples and the pi calls.
  • How the native agent works: how KanthorD builds an agent session on pi, the model configuration and its fallback chain, the prompt, the tools, the budget and the current limits.
  • What a worker reports to KanthorD: the state channel and the telemetry channel that a native worker and an external harness share.

For exact commands and API contracts, see the reference.
