How-to guides

These pages answer “How do I do this task?” Each guide is a short sequence of steps for one goal.

  • Run kanthord in a container: pull the published container image, run it with Podman or Docker, and connect a first repository with a dashboard SSH key.
  • Run kanthord on a Mac with Tailscale: run the single binary on a Mac and open the dashboard from a phone or a tablet on your tailnet.
  • Run kanthord on a VPS: run the single binary on a Linux server behind Caddy with a domain and HTTPS.
  • Run kanthord under a path prefix: run the single binary under a path such as /s/kanthord behind any reverse proxy, or on a home server with Cloudflare Tunnel and nginx.
  • Isolate worker instances in containers: run each instance of a worker binding in its own container on the host of the single binary. An agent command then reads no file of the server.
  • Add a toolchain to the worker image: build an image with Node.js or another toolchain for the server container.
  • Declare the affected tests of a repository: write the selector command and .kanthord/affected-tests.json, so that each implement node runs the tests that its change reaches.
  • Write the rules of a repository: name an instruction file such as AGENTS.md and write the Repository prompt and the Binding prompts, so that the coder and the reviewer read the same rules.

For the exact commands and options, see the reference.
