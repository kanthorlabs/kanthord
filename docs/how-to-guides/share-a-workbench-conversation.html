Share a Workbench conversation

Share one conversation of the Workbench with a guest. The guest needs no account. The guest opens a link, types a name, reads the conversation, writes notes and starts a run with a mention of an agent. You approve every act of that run.

Before you start

  • A running server, a signed-in dashboard and a conversation in the Workbench.
  • A guest must reach the server. Put the public host name of the link in gateway.allowed_hosts. When a reverse proxy serves the link, follow step 4 of the path prefix guide.
  • Keep the idle read timeout of the proxy above 15 seconds. The guest stream sends a keepalive every 15 seconds.

1. Create an invite

  1. Open the conversation and select Share.
  2. Under Invite for (required), type the name of the invitee. The name is a label of 1 to 64 characters.
  3. Under Projects (required, 1 to 50), pick the projects that the guest can work on. The dialog shows the hint “Select at least one project.” until you pick one.
  4. Select Create link.
  5. Select Copy link. The dialog shows the link once. After you close the dialog, no page shows it again.

The link has the form https://<host>/<base path>/join/<token>#name=<name>. The fragment after # never reaches the server.

Every live invite of the conversation shares one set of projects. When an invite is live, the dialog shows that set and locks the field. Revoke every invite to change the set.

2. Send the link

Send the link only to the invitee. The link is the only gate. Anyone who holds it joins until it expires or you revoke it. The link expires in 7 days.

The guest does these steps:

  1. Open the link. The page prefills the name.
  2. Change the name when needed, then select Join.

What the guest sees and does:

  • Guests see the whole history of the conversation, also the part from before the invite. The share dialog states this.
  • Guests see every answer in the conversation, your own runs included. Agents in guest runs read these answers too. Share a new conversation to keep other projects out.
  • Guests of a fork see its summary. The share dialog of a fork reads “This conversation carries a summary of <title>. Guests see the summary.”
  • Guests see the answers of the agents and the names of the tools that they call. They see no tool result, no tool input and no evidence content.
  • A guest writes notes. A note is a message with no leading mention. It starts no run.
  • A guest starts a run with a leading @<display name>. The run reads and acts only on the projects of the invite.
  • A guest can mention only an agent with no built-in tool, for example Yumi and Jeremy. A mention of SWE or RE is refused with 409 workbench.guest.agent_refused.
  • You approve every act of a guest run on its card. A guest never approves. Only you replace or stop the run and remove a queued message.
  • A guest sees the queue with no Edit, no Remove and no Stop.
  • A guest sees an action card with no button. Only you run the act.

In a shared conversation, your own message is also a note. Start a message with @<display name> to ask an agent.

3. Allow an evidence read

An evidence read in a shared conversation needs the typed node name. Guests see what the agent quotes, so the dashboard asks for more than a click.

  1. Read the card Evidence read in a shared conversation.
  2. Type the exact name of the node in the field.
  3. Select Allow, or select Reject.

A new invite clears every earlier grant of the conversation. The agent then asks again.

4. Revoke an invite

  1. Select Share.
  2. Select Revoke beside the name of the invitee.
  3. Select Revoke invite.

The guest loses access at once, and the link stops working. A revoke deletes the invite.

Result

The invitee reads the conversation, writes notes and starts runs for up to 7 days, or until you revoke the invite. The list of the share dialog shows each live invite with its name and expiry.

Troubleshooting

Symptom Cause and fix
workbench.invite.not_found at join The invite expired or you revoked it. Create a new invite.
gateway.jwt.invite_ended in a guest chat The invite ended while the guest was in the chat. Create a new invite.
workbench.invite.project_invalid The set holds no project, more than 50, a repeated id or an unknown project. Pick 1 to 50 existing projects.
workbench.invite.scope_mismatch A live invite of the conversation holds another set. Revoke every invite, then create the new invite.
workbench.guest.agent_refused The guest mentioned an agent with a built-in tool, such as SWE or RE. Mention Yumi or Jeremy.
workbench.invite.name_invalid The name is blank or holds more than 64 characters.
Allow stays disabled, or workbench.evidence.name_mismatch The typed text differs from the node name. Type the exact name.
The guest chat stops updating The proxy closed the stream. Raise its idle read timeout above 15 seconds and turn off response buffering.
